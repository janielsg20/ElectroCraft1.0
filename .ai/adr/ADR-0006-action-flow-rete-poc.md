# ADR-0006 — M00.6 Action Flow Rete POC

Status: `PROVISIONAL — SOURCE/RUNTIME GREEN, PUBLISHED-NPM GATE PENDING`
Date: 2026-08-17
Owner: F00 / M00.6

## Decision

ElectroCraft will persist a versioned, plain-JSON `ElectroCraftActionGraph`. Rete owns graph mechanics and workflow processing. The adapter maps the canonical graph to Rete nodes/connections at runtime and never persists Rete classes, node IDs generated by the engine, history stacks or editor internals.

The minimum canonical fixture is:

`Trigger(record.created) -> Condition(priority == high) -> Data(set status=processed) -> Toast("Registro procesado")`

The adapter generates separate Rete control/data connections from each logical canonical edge. `rete-engine` owns ControlFlow/Dataflow traversal. `rete-history-plugin` with `Presets.classic.setup()` owns node/connection undo/redo. A headless `BaseAreaPlugin` subclass exists only in the isolated POC harness because the official history preset requires an area parent; it is not product UI or a second history engine.

## Pinned engine set

- `rete@2.0.6`
- `rete-engine@2.1.1`
- `rete-history-plugin@2.2.0`
- `rete-area-plugin@2.3.2`
- transitive override: `@babel/runtime@7.29.7`

All are MIT. Direct Rete packages are pinned to the published npm versions; `@babel/runtime` is overridden to the latest compatible v7 observed during M00.6 so the dependency graph does not float inside `^7.21.0`.

Upstream release-tag note: GitHub tags `rete/v2.0.6`, `engine/v2.1.1` and `area-plugin/v2.3.2` contain source manifests whose internal `version` field still reflects the immediately previous release. Therefore npm is the source of truth for the installed package version, while the named Git tag/blob SHAs are used only as source/API provenance. The CI gate verifies the installed npm manifests directly.

## Ownership boundary

Rete owns:
- node/connection graph mechanics;
- ControlFlow traversal;
- Dataflow recursive data evaluation/cache behavior;
- history records and undo/redo mechanics.

ElectroCraft owns only:
- canonical action vocabulary;
- validation/fail-closed semantics;
- canonical-to-Rete mapping;
- runtime effects (`set` data operation, toast adapter semantics);
- persistence/export portability.

## Fail-closed rules frozen by this POC

- unknown node kind -> blocker;
- unsupported condition operator -> blocker;
- unsupported data operation -> blocker;
- unsafe data path (`__proto__`, `constructor`) -> blocker;
- missing node/edge references -> blocker;
- Rete engine objects in canonical persistence -> blocker.

# M26.3 — Mapear Pantallas, Templates y Componentes a bloques/patrones

**Fase propietaria:** F26 — Exportación WordPress Block Theme + Companion Plugin

## Por qué existe
WordPress tiene blocks, templates, template parts and patterns; creating a custom block for every ElectroCraft component would duplicate the platform.

## Resultado exacto
Al cerrar esta microfase, **Mapear Pantallas, Templates y Componentes a bloques/patrones** funciona de forma observable dentro del target correspondiente y pasa su gate. No se acepta un archivo generado sin validación ni una opción visual sin compiler/runtime real.

## Engine owner
`WordPress Block API + templates/parts/patterns`

## Responsabilidad ElectroCraft
ElectroCraft implementa únicamente el mapping desde modelos canónicos, la UX española, configuración, validación, diagnósticos, seguridad, compilación y evidencia. El framework/SDK target conserva routing/runtime/API behavior que ya ofrece.

## Precondiciones

- No existe un exporter paralelo para la misma responsabilidad.

## Implementación paso por paso
1. Create mapping decision ladder: core block -> attributes/styles -> pattern -> template/part -> dynamic block -> custom block.
2. Map Text/Image/Gallery/Button/List/etc. to native blocks where semantics match.
3. Map Header/Footer global templates to template parts.
4. Map Screens/content templates to block templates/custom templates.
5. Map Saved Blocks to patterns when appropriate.
6. Create custom/dynamic block only for unique runtime behavior.
7. Generate block.json and render callbacks only where necessary.
8. Test representative components and nested layouts.
9. Primero ejecuta mapping ladder a APIs WordPress nativas.
10. Genera Block Theme para diseño y Companion Plugin para comportamiento/datos.
11. Usa theme.json/blocks/CPT/tax/meta/options/REST/users/media antes de custom code/tables.
12. Ejecuta wp-env clean install/lifecycle/security tests.
13. Verifica Theme ZIP + Plugin ZIP checksums.

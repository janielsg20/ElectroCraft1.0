# M07.7 — Boundaries de compilers de navegación multi-target

**Fase propietaria:** F07 — Pantallas, navegación y rutas

## Por qué existe
El modelo de navegación debe ser portable y no depender de un router concreto.

## Resultado exacto
Al cerrar esta microfase, **Compilers Web/Expo boundaries** existe como capacidad real, conectada a los contratos de ElectroCraft y demostrada con pruebas. No se acepta placeholder, botón decorativo ni contrato sin consumidor.

## Engine owner
`React Router adapter contract + Expo Router adapter contract`

## Responsabilidad ElectroCraft
ElectroCraft conserva únicamente la semántica portable, la UX española, los adapters, permisos, validación, persistencia y compatibilidad multi-target. El engine OSS conserva la responsabilidad técnica para la que fue elegido.

## Ubicación de código obligatoria
- `packages/domain/src/navigation/`
- `packages/application/src/navigation/`
- `apps/studio/src/features/navigation/`

## Ubicación exacta en la app
No pantalla nueva; Compatibilidad mostrará gaps target cuando existan.

## Diseño visual exacto
Sin UI propia; tests/fixtures representan output compiler.

## Texto visible en español
No hay texto release salvo diagnostics traducidos.

## Ayuda contextual
Usa HelpRegistry `help.navigation.compiler`. El título de pantalla lleva `CircleHelp`; los conceptos técnicos usan `Info` solo cuando aportan contexto real.

## Precondiciones
- Gate de entrada de la fase satisfecho.
- Contratos/engines anteriores verdes.
- No existe una implementación paralela de la misma responsabilidad.

## Implementación paso por paso
1. Define `NavigationCompilerPort<TTargetOutput>` independiente de cualquier router.
2. Mantén ElectroCraftNavigation/Routes como única fuente canónica.
3. Define fixtures de salida para React Router y Expo Router sin generar source final todavía.
4. Define contract de ruta server para LAMP/Slim: method/path/name/params/guards.
5. Define contract WordPress: template/rewrite/page/custom endpoint mapping, sin guardar WP objects.
6. Define Capacitor como consumidor del Web router + deep-link adapter, no como otro navigation model.
7. Define Static rules: route pre-generation y blockers cuando la ruta depende de runtime mutable no representable.
8. Define capability diagnostics por navigator/route feature.
9. Test same Navigation model through all compiler contract fixtures.
10. No implementar exporter source completo dentro de F07.
11. Actualiza Navigation/Route contracts primero.
12. Implementa use-case/ref integrity.
13. Construye tree editor español.
14. Añade target compiler contract fixture sin persistir router objects.
15. Prueba params/deep-links/guards/ref rename.

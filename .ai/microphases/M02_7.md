# M02.7 — Definir ElectroCraftExportIR

**Fase propietaria:** F02 — Modelo canónico de App y ownership

## Por qué existe
Esta microfase existe para **Definir ElectroCraftExportIR** dentro de la responsabilidad de `F02`: definir ownership/modelos portables mínimos. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **Definir ElectroCraftExportIR** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

## Engine owner
`Zod boundaries`

### Regla
Antes de escribir código, consulta la API pública del engine. Si ya existe la capacidad, úsala. ElectroCraft solo debe aportar canonical mapping, configuración, UX, adapter, target semantics o exportación.

## Implementación línea por línea
1. Define `ElectroCraftExportIR` como snapshot immutable/versionado del proyecto canónico.
2. Incluye Documents, Navigation, Data Sources sanitized definitions, DataSchema, Queries, State, Actions, Forms, Roles, Theme, Media manifest y capability requirements.
3. Excluye Studio workspace state, Puck/Rete histories, TanStack cache, AI history/prompts y secret values.
4. Define `ExportTargetId` como closed versioned set inicial: local-project, react-web, static-web, pwa, android-expo, ios-expo, capacitor, lamp, wordpress.
5. TargetId no cambia la forma canónica del IR; los compilers leen el mismo snapshot.
6. Define `TargetCompileContext` con target ID, config validada, capabilities, environment/toolchain facts y secret refs.
7. Define deterministic serialization/checksum para que dos exporters reciban exactamente la misma revision.
8. Añade `ExportValidationReport` previo a target compilation.
9. Contract-test que target-specific objects (Slim routes, WP blocks, Expo route files, Capacitor config) no entren al ExportIR.
10. Documenta version/migration policy.
11. Define/actualiza schema TypeScript/Zod en domain/contracts.
12. Añade referencias IDs, versioning y validation.
13. Implementa serializer/migration si el shape persistido cambia.
14. Añade application-facing types sin importar engines.
15. Añade fixture round-trip y boundary test.

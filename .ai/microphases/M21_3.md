# M21.3 — Runtime de datos, estado, forms y actions Web

**Fase propietaria:** F21 — Runtime Web y exportación React/PWA

## Por qué existe
Una app generada debe ejecutar datos/estado/formularios/acciones sin depender de Refine o del Studio.

## Resultado exacto
Al cerrar esta microfase, **Runtime de datos, estado, forms y actions Web** existe como capacidad real, conectada a los contratos de ElectroCraft y demostrada con pruebas. No se acepta placeholder, botón decorativo ni contrato sin consumidor.

## Engine owner
`TanStack Query + Zustand + RHF/Zod + ElectroCraftAction runtime`

## Responsabilidad ElectroCraft
ElectroCraft conserva únicamente la semántica portable, la UX española, los adapters, permisos, validación, persistencia y compatibilidad multi-target. El engine OSS conserva la responsabilidad técnica para la que fue elegido.

## Ubicación de código obligatoria
- `packages/runtime-web/`
- `packages/export-web/`
- `packages/export-core/`

## Ubicación exacta en la app
`Vista previa Web` y app exportada.

## Diseño visual exacto
No UI de engine; los errores aparecen en componentes/runtime Debug.

## Texto visible en español
Datos cargando…; Reintentar; Guardando…; Guardado; Error de validación.

## Ayuda contextual
Usa HelpRegistry `help.runtime.data`. El título de pantalla lleva `CircleHelp`; los conceptos técnicos usan `Info` solo cuando aportan contexto real.

## Precondiciones
- Gate de entrada de la fase satisfecho.
- Contratos/engines anteriores verdes.
- No existe una implementación paralela de la misma responsabilidad.

## Implementación paso por paso
1. Configura Query client desde runtime policies.
2. Instancia DataSource adapters requeridos por el proyecto.
3. Instancia Zustand stores generados desde StateDefinitions.
4. Ejecuta Forms con RHF/Zod.
5. Ejecuta ActionGraphs mediante runtime portable/adapter aprobado.
6. Redacta secrets y usa ConnectorGateway refs.
7. Prueba query cache, state, submit, mutation invalidation y action navigation.
8. Congela ExportIR revision.
9. Genera runtime/source mediante shared Web compilers.
10. Genera target-specific package/profile.
11. Ejecuta dependency pruning.
12. Ejecuta install/build/serve/reimport verifier según target.
13. Registra artifact/checksum/report.

## Artefactos obligatorios al cerrar
- `WebRuntimeProviders`
- `runtime data/action tests`

## Estados UI obligatorios
- Inicial.
- Cargando, solo cuando haya espera perceptible.
- Vacío con explicación y CTA.
- Error en español con recuperación.
- Deshabilitado con motivo.
- Guardando/Aplicando cuando corresponda.
- Éxito breve y accionable.

## Responsive
- Desktop: alta densidad sin comprimir la tarea principal.
- Tablet: panel secundario a Sheet/Drawer.
- Mobile: flujo por rutas/pasos; no reducir una UI desktop de tres columnas.

## Accesibilidad
- teclado;
- focus-visible;
- labels persistentes;
- icon-only con aria-label;
- errores anunciables;
- touch targets;
- reduced motion;
- alternativa a drag cuando aplique.

## Prohibido
- No incluir Refine en una app normal sin Admin screens.
- No crear cache/state engine paralelo.

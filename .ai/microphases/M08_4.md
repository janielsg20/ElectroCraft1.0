# M08.4 — GraphQL Connector

**Fase propietaria:** F08 — Fuentes de datos, modelos internos, registros y conectores

## Por qué existe
GraphQL es un formato común de APIs y debe entrar como adapter, no como un query engine paralelo.

## Resultado exacto
Al cerrar esta microfase, **GraphQL Connector** existe como capacidad real, conectada a los contratos de ElectroCraft y demostrada con pruebas. No se acepta placeholder, botón decorativo ni contrato sin consumidor.

## Engine owner
`GraphQL over fetch + DataSourceAdapter`

## Responsabilidad ElectroCraft
ElectroCraft conserva únicamente la semántica portable, la UX española, los adapters, permisos, validación, persistencia y compatibilidad multi-target. El engine OSS conserva la responsabilidad técnica para la que fue elegido.

## Ubicación de código obligatoria
- `packages/connectors/`
- `packages/data-web/`
- `packages/domain/src/data/`
- `apps/studio/src/features/data/`

## Ubicación exacta en la app
`Datos > Fuentes de datos > Nueva fuente > GraphQL`.

## Diseño visual exacto
Wizard similar a REST; schema/introspection browser y operation editor con variables. Raw query vive en Advanced.

## Texto visible en español
GraphQL; Endpoint; Esquema; Consultas; Mutaciones; Variables; Probar.

## Ayuda contextual
Usa HelpRegistry `help.data.graphql`. El título de pantalla lleva `CircleHelp`; los conceptos técnicos usan `Info` solo cuando aportan contexto real.

## Precondiciones
- Gate de entrada de la fase satisfecho.
- Contratos/engines anteriores verdes.
- No existe una implementación paralela de la misma responsabilidad.

## Implementación paso por paso
1. Define GraphQL source config endpoint/authRef/headers.
2. Obtén schema por introspection solo cuando el endpoint lo permite.
3. Permite seleccionar fields/arguments para generar operation definitions; raw document queda Advanced.
4. Variables se enlazan mediante mappings tipados.
5. Normaliza data/errors a DataResult.
6. Usa ConnectorGateway cuando CORS/secret policy lo exige.
7. Prueba introspection allowed/denied, query, mutation, variables y GraphQL errors.
8. Define DataSource/DataModel contract/capabilities.
9. Implementa adapter/repository behind ConnectorRegistry.
10. Resuelve secrets por SecretRef/Gateway.
11. Construye Data UI/Explorer/Model UI indicada.
12. Prueba schema/capabilities/CRUD/error/security.

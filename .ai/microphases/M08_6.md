# M08.6 — Data Explorer y prueba de operaciones

**Fase propietaria:** F08 — Fuentes de datos, modelos internos, registros y conectores

## Por qué existe
El usuario necesita entender una fuente antes de enlazarla a pantallas.

## Resultado exacto
Al cerrar esta microfase, **Data Explorer y prueba de operaciones** existe como capacidad real, conectada a los contratos de ElectroCraft y demostrada con pruebas. No se acepta placeholder, botón decorativo ni contrato sin consumidor.

## Engine owner
`ConnectorRegistry + DataSourceAdapter`

## Responsabilidad ElectroCraft
ElectroCraft conserva únicamente la semántica portable, la UX española, los adapters, permisos, validación, persistencia y compatibilidad multi-target. El engine OSS conserva la responsabilidad técnica para la que fue elegido.

## Ubicación de código obligatoria
- `packages/connectors/`
- `packages/data-web/`
- `packages/domain/src/data/`
- `apps/studio/src/features/data/`

## Ubicación exacta en la app
`Datos > Fuentes de datos > <fuente> > Explorar`.

## Diseño visual exacto
Left resources/operations 260; center parameter form + Run; result panel table/JSON preview; Advanced muestra raw trace sanitizada.

## Texto visible en español
Explorar; Recurso; Operación; Parámetros; Ejecutar; Resultado; Tiempo; Error.

## Ayuda contextual
Usa HelpRegistry `help.data.explorer`. El título de pantalla lleva `CircleHelp`; los conceptos técnicos usan `Info` solo cuando aportan contexto real.

## Precondiciones
- Gate de entrada de la fase satisfecho.
- Contratos/engines anteriores verdes.
- No existe una implementación paralela de la misma responsabilidad.

## Implementación paso por paso
1. Lista resources/operations según schema/capabilities.
2. Genera parameter controls desde operation schema.
3. Ejecuta solo con acción explícita `Ejecutar`; mutaciones requieren confirmación.
4. Renderiza table/list para objetos/arrays y JSON tree Advanced.
5. Redacta auth headers/secrets.
6. Permite `Crear consulta desde esta operación` que crea draft QueryDefinition.
7. Prueba read, mutation confirm, large result truncation y errors.
8. Define DataSource/DataModel contract/capabilities.
9. Implementa adapter/repository behind ConnectorRegistry.
10. Resuelve secrets por SecretRef/Gateway.
11. Construye Data UI/Explorer/Model UI indicada.
12. Prueba schema/capabilities/CRUD/error/security.

## Responsive
- Desktop: alta densidad sin comprimir la tarea principal.
- Tablet: panel secundario a Sheet/Drawer.
- Mobile: flujo por rutas/pasos; no reducir una UI desktop de tres columnas.

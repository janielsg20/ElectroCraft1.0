# M21.12 — Generar professionalStudio manifest portable

**Fase propietaria:** F21 — Runtime Web y exportación React/PWA

## Por qué existe
Preservar modelos y capacidades avanzadas junto con cada export sin obligar al runtime a cargar el Studio.

## Resultado exacto
Al cerrar esta microfase, **Generar professionalStudio manifest portable** debe quedar integrado, persistido/exportable cuando corresponda y cubierto por pruebas. No basta con un tipo, un botón o un placeholder.

## Engine owner
`ElectroCraftExportIR + target generators`

## Responsabilidad ElectroCraft
Construye únicamente la semántica portable, adapter, configuración, UX y diagnostics que el engine no trae. No dupliques el motor.

## Ubicación visual
Publicar > Exportar y generated output reports.

## Ubicación de código obligatoria
- `packages/runtime-web/`
- `packages/export-web/`
- `packages/export-core/`

## Ubicación exacta en la app
No separate user control; included automatically where defined, documented in Export result.

## Diseño visual exacto
Advanced manifest details expandable.

## Texto visible en español
Exportar; Local; React; Estático; PWA; Analizar; Generar; Resultado.

## Ayuda contextual
Usa HelpRegistry `help.export`. Si esta microfase introduce un concepto nuevo, añade/actualiza su HelpDescriptor en español. La ayuda crítica no puede vivir solo en un tooltip.

## Precondiciones
- La microfase anterior de la fase está COMPLETADA o la dependencia está documentada como ya disponible.
- Los contratos canónicos necesarios existen.
- El engine owner está encapsulado detrás del adapter correspondiente.

## Implementación línea por línea
1. Genera `professionalStudio` manifest portable dentro del Local package y React/PWA source cuando la opción de metadata profesional esté activada.
2. Incluye schema/navigation/actions/component capability IDs y migration/source version.
3. Excluye Puck/Rete histories, workspace preferences, AI prompts/history y secrets.
4. El runtime puede ignorarlo; sirve para trazabilidad/import futuro.
5. Capacitor, LAMP y WordPress consumen este manifest en sus fases Core respectivas; F21 solo valida su producción portable.
6. Test round-trip del manifest en Local package y React export metadata.
7. Congela ExportIR revision.
8. Genera runtime/source mediante shared Web compilers.
9. Genera target-specific package/profile.
10. Ejecuta dependency pruning.
11. Ejecuta install/build/serve/reimport verifier según target.
12. Registra artifact/checksum/report.

## Responsive y accesibilidad si toca UI
- Desktop high-density sin overflow.
- Tablet usa Sheet/Drawer para tooling secundario.
- Mobile usa route/card/bottom-sheet, no desktop comprimido.
- Keyboard/focus-visible/aria-label.
- Alternative a DnD/gestos.

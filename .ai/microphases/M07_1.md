# M07.1 — Modelo de Pantalla, Ruta y Navigation Graph

**Fase propietaria:** F07 — Pantallas, navegación y rutas

## Por qué existe
Un App Builder debe modelar pantallas y navegación antes de conectar datos o lógica.

## Resultado exacto
Al cerrar esta microfase, **Modelo de Pantalla, Ruta y Navigation Graph** existe como capacidad real, conectada a los contratos de ElectroCraft y demostrada con pruebas. No se acepta placeholder, botón decorativo ni contrato sin consumidor.

## Engine owner
`ElectroCraftDocument + ElectroCraftRoute/Navigation contracts`

## Responsabilidad ElectroCraft
ElectroCraft conserva únicamente la semántica portable, la UX española, los adapters, permisos, validación, persistencia y compatibilidad multi-target. El engine OSS conserva la responsabilidad técnica para la que fue elegido.

## Ubicación de código obligatoria
- `packages/domain/src/navigation/`
- `packages/application/src/navigation/`
- `apps/studio/src/features/navigation/`

## Ubicación exacta en la app
`Construir > Pantallas` y `App > Navegación`.

## Diseño visual exacto
Pantallas usa list/tree + detail; Navegación usa tree/diagram sencillo con patterns Stack/Tabs/Drawer/Modal.

## Texto visible en español
Pantallas; Nueva pantalla; Navegación; Ruta; Pantalla inicial; Pestañas; Menú lateral; Modal; Parámetros.

## Ayuda contextual
Usa HelpRegistry `help.navigation`. El título de pantalla lleva `CircleHelp`; los conceptos técnicos usan `Info` solo cuando aportan contexto real.

## Precondiciones
- Gate de entrada de la fase satisfecho.
- Contratos/engines anteriores verdes.
- No existe una implementación paralela de la misma responsabilidad.

## Implementación paso por paso
1. Cambia el kind principal visual de `page` a `screen`; conserva `template|form|admin-screen|reusable-component`.
2. Define ElectroCraftRouteDefinition con path/name/screenRef/params/guards/deepLink metadata.
3. Define ElectroCraftNavigationDefinition con root navigator y nodes `stack|tabs|drawer|modal|screen`.
4. No copies Expo/React Router objects into canonical model.
5. Añade validators de cycles, duplicate routes, missing screens e invalid initial route.
6. Actualiza serializer/migrations desde nomenclatura Page legacy si existe.
7. Actualiza Navigation/Route contracts primero.
8. Implementa use-case/ref integrity.
9. Construye tree editor español.
10. Añade target compiler contract fixture sin persistir router objects.
11. Prueba params/deep-links/guards/ref rename.

## Artefactos obligatorios al cerrar
- `ElectroCraftDocument kind=screen`
- `ElectroCraftRouteDefinition`
- `ElectroCraftNavigationDefinition`
- `migration tests`

## Estados UI obligatorios
- Inicial.
- Cargando, solo cuando haya espera perceptible.
- Vacío con explicación y CTA.
- Error en español con recuperación.
- Deshabilitado con motivo.
- Guardando/Aplicando cuando corresponda.
- Éxito breve y accionable.

## Responsive
- Desktop: alta densidad sin comprimir la tarea principal.
- Tablet: panel secundario a Sheet/Drawer.
- Mobile: flujo por rutas/pasos; no reducir una UI desktop de tres columnas.

## Accesibilidad
- teclado;
- focus-visible;
- labels persistentes;
- icon-only con aria-label;
- errores anunciables;
- touch targets;
- reduced motion;
- alternativa a drag cuando aplique.

## Pruebas obligatorias
1. Screen/route round-trip.
2. Invalid initial screen.
3. Cycle/duplicate route.
4. Legacy page migration.
90. lint.
91. typecheck.

## Prohibido
- No crear WebRoutes y NativeRoutes separados.
- No usar file paths de Expo como IDs canónicos.

# M18.8 — Generar pantallas, secciones, bloques, componentes, plantillas y temas

**Fase propietaria:** F18 — Generar con IA — Gemini

## Por qué existe
Esta es la capacidad principal de diseño asistido: producir artifacts reales del editor, no imágenes de mockup sin estructura.

## Resultado exacto
Al cerrar esta microfase, **Generar páginas, secciones, bloques, componentes, plantillas y temas** está implementada de extremo a extremo para su alcance y produce evidencia real.

## Engine owner
`Puck-compatible ElectroCraftDocument/Theme contracts + Gemini structured generation`

## Responsabilidad ElectroCraft
ElectroCraft controla contratos, contexto, UX en español, permisos, validación, borradores, diff y Apply. El proveedor de IA nunca muta el proyecto directamente.

## Ubicación de código obligatoria
- `packages/ai/`
- `apps/studio/src/features/ai/`
- `apps/studio/src/components/ai-elements/`

## Ubicación exacta en la app
`Construir > Generar con IA > Qué quieres generar`: Pantalla, Sección, Componente, Plantilla, Tema.

## Diseño visual exacto
Preview usa el renderer real. Changes tab muestra árbol/props/tokens añadidos/modificados.

## Texto y ayuda
Todo texto visible usa i18n español. El título de la sección lleva `CircleHelp`; las opciones técnicas no obvias usan `Info` con HelpRegistry. Nunca mostrar raw provider errors como texto principal.

## Texto visible en español
Generar con IA; Crear; Historial; Contexto; Opciones; Validación; Generar; Aplicar cambios; Guardar como reutilizable.

## Ayuda contextual
Usa HelpRegistry `help.ai`. Si esta microfase introduce un concepto nuevo, añade/actualiza su HelpDescriptor en español. La ayuda crítica no puede vivir solo en un tooltip.

## Precondiciones
- F17 COMPLETADA: los tipos de artifact reutilizable y ElectroCraftExtensionPackage existen.
- F00 POC Gemini aprobado.
- i18n/HelpRegistry/AppShell disponibles.
- provider secrets fuera del cliente.

## Implementación paso por paso
1. Para Pantalla genera ElectroCraftDocument kind=screen con Core/Presets/Blocks existentes.
2. Para Sección genera subtree y ofrece Guardar como bloque.
3. Para Componente intenta Core props -> Preset -> Block -> Global Component antes de proponer nueva ComponentDefinition.
4. Si unique behavior requiere ComponentDefinition nueva, draft queda `Requiere revisión` y explica por qué un Block no basta.
5. Para Template genera document kind=template + display conditions draft.
6. Para Tema genera ElectroCraftTheme/tokens/variants; no Apariencia del Studio.
7. Run slot/prop/layout/responsive/a11y validators.
8. Preview Desktop/Tablet/Mobile before Apply.
9. Allow regeneration scoped to selected subtree/token group rather than entire artifact.
10. Save reusable artifact to natural library only after user confirmation.
11. Define request/draft schema antes de prompt/UI.
12. Usa AI SDK para model/tools/structured output y AI Elements para UI estándar.
13. Todas las tools escriben Draft o leen contexto sanitizado.
14. Valida/Preview/Diff antes de Apply.
15. Aplica solo por AIApplyService transaccional.
16. Prueba mock determinista + security + Spanish.

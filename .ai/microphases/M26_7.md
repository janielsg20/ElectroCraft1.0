# M26.7 — Usuarios, permisos, Administración y Medios WordPress

**Fase propietaria:** F26 — Exportación WordPress Block Theme + Companion Plugin

## Por qué existe
WordPress already has users, roles, capabilities, Media Library and Admin; exporter should adapt to those primitives.

## Resultado exacto
Al cerrar esta microfase, **Usuarios, permisos, Administración y Medios WordPress** funciona de forma observable dentro del target correspondiente y pasa su gate. No se acepta un archivo generado sin validación ni una opción visual sin compiler/runtime real.

## Engine owner
`WordPress Users/Roles/Capabilities/Media/Admin + @wordpress packages`

## Responsabilidad ElectroCraft
ElectroCraft implementa únicamente el mapping desde modelos canónicos, la UX española, configuración, validación, diagnósticos, seguridad, compilación y evidencia. El framework/SDK target conserva routing/runtime/API behavior que ya ofrece.

## Ubicación de código obligatoria
- `packages/export-wordpress/`
- `packages/export-core/`
- `fixtures/wordpress/`

## Ubicación exacta en la app
`Publicar > Exportar > WordPress > Administración y acceso`.

## Diseño visual exacto
Mapping summary shows ElectroCraft roles/capabilities -> WP caps, admin screens, media mapping. Complex plugin UI may use WP packages.

## Texto visible en español
Usuarios; Roles; Capacidades; Administración; Biblioteca de medios; Permisos.

## Ayuda contextual
Usa HelpRegistry `help.export.wordpress.admin`. El H1 usa `CircleHelp`; las opciones técnicas muestran Info solo cuando explican una decisión o requisito del target.

## Precondiciones
- Gate de la fase anterior satisfecho.
- ExportIR/TargetRegistry/Capability Analyzer disponibles.
- Tests existentes verdes antes de modificar el target.
- No existe un exporter paralelo para la misma responsabilidad.

## Implementación paso por paso
1. Map roles to WordPress roles/capabilities with namespaced custom caps.
2. Enforce capabilities in handlers/REST/admin, not only visibility.
3. Map media assets/fields to Media Library attachment IDs where imported.
4. Generate admin menus/screens only when project includes Administration.
5. Prefer native WP admin patterns and @wordpress packages; externalize WordPress-provided JS deps instead of bundling duplicate React.
6. Map audit/history according to project features and WP data.
7. Test denied access and media upload/select.
8. Primero ejecuta mapping ladder a APIs WordPress nativas.
9. Genera Block Theme para diseño y Companion Plugin para comportamiento/datos.
10. Usa theme.json/blocks/CPT/tax/meta/options/REST/users/media antes de custom code/tables.
11. Ejecuta wp-env clean install/lifecycle/security tests.
12. Verifica Theme ZIP + Plugin ZIP checksums.

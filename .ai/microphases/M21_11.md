# M21.11 — Generar Runtime Dependency Manifest y podar dependencias

**Fase propietaria:** F21 — Runtime Web y exportación React/PWA

## Por qué existe
Impedir que los proyectos exportados carguen editores/engines que no necesitan.

## Resultado exacto
Al cerrar esta microfase, **Generar Runtime Dependency Manifest y podar dependencias** debe quedar integrado, persistido/exportable cuando corresponda y cubierto por pruebas. No basta con un tipo, un botón o un placeholder.

## Engine owner
`ElectroCraftExportIR + target generators`

## Responsabilidad ElectroCraft
Construye únicamente la semántica portable, adapter, configuración, UX y diagnostics que el engine no trae. No dupliques el motor.

## Ubicación visual
Publicar > Exportar y generated output reports.

## Ubicación de código obligatoria
- `packages/runtime-web/`
- `packages/export-web/`
- `packages/export-core/`

## Ubicación exacta en la app
`Exportar > <target> > Dependencias` Advanced/summary.

## Diseño visual exacto
Human dependency list with reason; not raw package graph by default.

## Texto visible en español
Exportar; Local; React; Estático; PWA; Analizar; Generar; Resultado.

## Ayuda contextual
Usa HelpRegistry `help.export`. Si esta microfase introduce un concepto nuevo, añade/actualiza su HelpDescriptor en español. La ayuda crítica no puede vivir solo en un tooltip.

## Precondiciones
- La microfase anterior de la fase está COMPLETADA o la dependencia está documentada como ya disponible.
- Los contratos canónicos necesarios existen.
- El engine owner está encapsulado detrás del adapter correspondiente.

## Implementación línea por línea
1. Analiza ExportIR y produce RuntimeDependencyManifest para Web/PWA.
2. Incluye cada dependency con capability/reason.
3. Excluye Puck, Rete editor/history, AI Workbench y Studio settings.
4. Incluye `rete-engine`/Action runtime solo si Web ejecuta workflows client-side.
5. Incluye Refine solo si la app exporta Administración.
6. Incluye Tiptap editor solo si hay edición richtext; read-only usa static renderer/helper.
7. Incluye connector runtime únicamente para Data Sources usadas.
8. Native-specific packages jamás aparecen en Web manifest.
9. Test minimal screen, data app, admin app y workflow app.
10. Congela ExportIR revision.
11. Genera runtime/source mediante shared Web compilers.
12. Genera target-specific package/profile.
13. Ejecuta dependency pruning.
14. Ejecuta install/build/serve/reimport verifier según target.
15. Registra artifact/checksum/report.

## Artefactos obligatorios al cerrar
- `RuntimeDependencyManifest`
- `dependency pruning tests`

## Estados y errores
- Define empty/loading/error/disabled/blocked cuando tengan sentido.
- Un caso unsupported nunca se convierte silenciosamente en success.
- Diagnostics deben incluir código, ubicación, causa y acción sugerida.

## Responsive y accesibilidad si toca UI
- Desktop high-density sin overflow.
- Tablet usa Sheet/Drawer para tooling secundario.
- Mobile usa route/card/bottom-sheet, no desktop comprimido.
- Keyboard/focus-visible/aria-label.
- Alternative a DnD/gestos.

## Pruebas obligatorias
1. Unit/contract del valor Electro.
2. Integration con engine/storage real.
3. Negative/failure path.
4. Round-trip si persiste canonical data.
5. E2E si existe UI.
6. Target fixture si afecta export/native/server.
7. lint.
8. typecheck.
9. test.
10. build.

## Prohibido
- No crear subsystem paralelo.
- No persistir engine internals como modelo canónico.
- No usar mocks permanentes.

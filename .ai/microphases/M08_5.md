# M08.5 — ConnectorGateway y SecretStore

**Fase propietaria:** F08 — Fuentes de datos, modelos internos, registros y conectores

## Por qué existe
Conectores externos no pueden exponer credenciales SQL/API en browser o apps generadas.

## Resultado exacto
Al cerrar esta microfase, **ConnectorGateway y SecretStore** existe como capacidad real, conectada a los contratos de ElectroCraft y demostrada con pruebas. No se acepta placeholder, botón decorativo ni contrato sin consumidor.

## Engine owner
`ConnectorGatewayPort + SecretStorePort`

## Responsabilidad ElectroCraft
ElectroCraft conserva únicamente la semántica portable, la UX española, los adapters, permisos, validación, persistencia y compatibilidad multi-target. El engine OSS conserva la responsabilidad técnica para la que fue elegido.

## Ubicación de código obligatoria
- `packages/connectors/`
- `packages/data-web/`
- `packages/domain/src/data/`
- `apps/studio/src/features/data/`

## Ubicación exacta en la app
`Configuración > Integraciones > Gateway y secretos`; cada Fuente de datos muestra solo referencias/estado.

## Diseño visual exacto
Settings Sheet con estado Gateway, environments Desarrollo/Producción y lista de secretos por nombre; valores nunca se vuelven a mostrar completos.

## Texto visible en español
Gateway de conectores; Secretos; Desarrollo; Producción; Configurado; Falta configuración; Probar conexión.

## Ayuda contextual
Usa HelpRegistry `help.data.secrets`. El título de pantalla lleva `CircleHelp`; los conceptos técnicos usan `Info` solo cuando aportan contexto real.

## Precondiciones
- Gate de entrada de la fase satisfecho.
- Contratos/engines anteriores verdes.
- No existe una implementación paralela de la misma responsabilidad.

## Implementación paso por paso
1. Define SecretRef y environment scopes.
2. Implementa SecretStorePort; development adapter puede usar server env, production requiere server/secret manager.
3. Define ConnectorGatewayPort para ejecutar operaciones que no deben ir directas desde cliente.
4. El proyecto exporta nombres/refs y `.env.example`, nunca valores.
5. UI permite crear/reemplazar secret sin read-back del valor.
6. DataSourceAdapter decide direct/gateway según capability/security.
7. Prueba bundle/export/log secret scan.
8. Define DataSource/DataModel contract/capabilities.
9. Implementa adapter/repository behind ConnectorRegistry.
10. Resuelve secrets por SecretRef/Gateway.
11. Construye Data UI/Explorer/Model UI indicada.
12. Prueba schema/capabilities/CRUD/error/security.

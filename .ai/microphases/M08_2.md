# M08.2 — Fuente interna ElectroCraft Data sobre PGlite

**Fase propietaria:** F08 — Fuentes de datos, modelos internos, registros y conectores

## Por qué existe
La app necesita una base de datos local integrada para prototipos, apps offline y datos internos sin obligar a un servidor.

## Resultado exacto
Al cerrar esta microfase, **Fuente interna ElectroCraft Data sobre PGlite** existe como capacidad real, conectada a los contratos de ElectroCraft y demostrada con pruebas. No se acepta placeholder, botón decorativo ni contrato sin consumidor.

## Engine owner
`PGlite + Drizzle + existing generic record store`

## Responsabilidad ElectroCraft
ElectroCraft conserva únicamente la semántica portable, la UX española, los adapters, permisos, validación, persistencia y compatibilidad multi-target. El engine OSS conserva la responsabilidad técnica para la que fue elegido.

## Ubicación de código obligatoria
- `packages/connectors/`

## Ubicación exacta en la app
`Datos > Fuentes de datos > ElectroCraft Data` y `Datos > Registros/Modelos`.

## Diseño visual exacto
Source detail muestra estado `Local`, tamaño aproximado, modelos, registros y acciones de backup; no muestra consola SQL en beginner.

## Texto visible en español
ElectroCraft Data; Local; Disponible sin conexión; Modelos; Registros; Copia de seguridad.

## Ayuda contextual
Usa HelpRegistry `help.data.internal`. El título de pantalla lleva `CircleHelp`; los conceptos técnicos usan `Info` solo cuando aportan contexto real.

## Precondiciones
- Gate de entrada de la fase satisfecho.
- Contratos/engines anteriores verdes.
- No existe una implementación paralela de la misma responsabilidad.

## Implementación paso por paso
1. Implementa `InternalDataSourceAdapter` sobre los services/repositories PGlite existentes.
2. Mapea Content/Data Models a resources del adapter sin crear otro store físico.
3. Expone CRUD/query capabilities que luego consumen QueryRuntime y Admin.
4. Respeta project transaction/revision boundaries cuando una operación altera schema metadata.
5. Expone schema discovery a partir de ElectroCraftDataSchema, no introspección física para UI.
6. Marca el source como offline-capable.
7. Prueba CRUD, reopen, migration, offline y permission boundary.
8. Define DataSource/DataModel contract/capabilities.
9. Implementa adapter/repository behind ConnectorRegistry.
10. Resuelve secrets por SecretRef/Gateway.
11. Construye Data UI/Explorer/Model UI indicada.
12. Prueba schema/capabilities/CRUD/error/security.

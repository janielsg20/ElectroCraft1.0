# M24.4 — Plugins, capacidades y permisos Capacitor

**Fase propietaria:** F24 — Exportación Capacitor

## Por qué existe
Las capacidades nativas deben resolverse a plugins Capacitor solo cuando el proyecto las usa.

## Resultado exacto
Al cerrar esta microfase, **Plugins, capacidades y permisos Capacitor** funciona de forma observable dentro del target correspondiente y pasa su gate. No se acepta un archivo generado sin validación ni una opción visual sin compiler/runtime real.

## Engine owner
`Capacitor plugins + ElectroCraft CapabilityRegistry`

## Responsabilidad ElectroCraft
ElectroCraft implementa únicamente el mapping desde modelos canónicos, la UX española, configuración, validación, diagnósticos, seguridad, compilación y evidencia. El framework/SDK target conserva routing/runtime/API behavior que ya ofrece.

## Ubicación de código obligatoria
- `packages/export-capacitor/`
- `packages/export-core/`

## Ubicación exacta en la app
`Publicar > Exportar > Capacitor > Plugins/Permisos`.

## Diseño visual exacto
Lista capability -> plugin -> plataforma -> permiso -> estado. Chips `Incluido`, `Adaptado`, `Bloqueado`.

## Texto visible en español
Plugins; Permisos; Incluido; Requiere configuración; No compatible; Ir al origen.

## Ayuda contextual
Usa HelpRegistry `help.export.capacitor.plugins`. El H1 usa `CircleHelp`; las opciones técnicas muestran Info solo cuando explican una decisión o requisito del target.

## Precondiciones
- Gate de la fase anterior satisfecho.
- ExportIR/TargetRegistry/Capability Analyzer disponibles.
- Tests existentes verdes antes de modificar el target.
- No existe un exporter paralelo para la misma responsabilidad.

## Implementación paso por paso
1. Crea mapping registry de capability IDs a plugins oficiales/aprobados.
2. Incluye solo plugins usados.
3. Compila permission descriptions/config Android/iOS.
4. Si una capability no tiene mapping seguro, emite blocker.
5. Mapea Files, Camera, Location, Notifications, Haptics, Share, Contacts, Calendar, Biometrics según soporte verificado.
6. No inventes plugin name/version: se verifica al implementar.
7. Prueba dependency pruning y diagnostics.
8. Reutiliza Web Runtime, no dupliques React exporter.
9. Genera Capacitor config/platform projects.
10. Incluye solo plugins/capabilities usados.
11. Ejecuta sync/build verification.
12. Comprueba no Expo dependency leakage.
13. Registra artifact/report.

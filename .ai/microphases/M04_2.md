# M04.2 — Inicializar PGlite Multi-Tab Worker y migrations

**Fase propietaria:** F04 — Persistencia local, proyectos y revisiones

## Por qué existe
Esta microfase existe para **Inicializar PGlite Multi-Tab Worker y migrations** dentro de la responsabilidad de `F04`: persistir incrementalmente y gestionar proyectos/revisiones. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **Inicializar PGlite Multi-Tab Worker y migrations** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

`PGlite/Drizzle + OPFS`

## Implementación línea por línea
1. Ejecuta PGlite detrás del Worker multi-tab oficial; no abras PGlite directamente desde React components.
2. Usa una única DB lógica del Studio y leader election/proxy del Worker.
3. Como baseline de compatibilidad, configura un `dataDir` IndexedDB persistente (`idb://...`) salvo que F00 benchmark/compatibility apruebe explícitamente otro filesystem.
4. OPFS AHP para la propia DB es una optimización opcional, no el default universal: feature-detect y prueba navegadores soportados antes de activarlo.
5. Usa Drizzle sobre la conexión expuesta por StudioDatabasePort; UI nunca recibe client raw.
6. Configura Vite conforme a PGlite: excluye `@electric-sql/pglite` de dependency optimization y usa worker format compatible con multi-tab build.
7. Define lifecycle bootstrap -> migrations -> health check -> repositories ready.
8. Escucha leader change para revalidar health/query invalidation sin crear otra DB independiente.
9. Prueba dos tabs/worker clients escribiendo/leyendo el mismo project y leader handoff.
10. Cambia primero repository/service contract.
11. Implementa Drizzle/PGlite transaction/migration.
12. Conecta use-case; UI nunca llama PGlite directamente.
13. Añade save/reopen/recovery behavior.
14. Añade migration/integration fixture.

# M12.5 — Refine Audit/Notification integration

**Fase propietaria:** F12 — Usuarios, autenticación y permisos

## Por qué existe
Esta microfase existe para **Refine Audit/Notification integration** dentro de la responsabilidad de `F12`: resolver auth/permissions/audit. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **Refine Audit/Notification integration** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

## Engine owner
`Refine Access/Auth/Audit`

Antes de escribir código, consulta la API pública del engine. Si ya existe la capacidad, úsala. ElectroCraft solo debe aportar canonical mapping, configuración, UX, adapter, target semantics o exportación.

## Implementación línea por línea
1. Refine `NotificationProvider` es el owner de feedback CRUD/admin; mapea sus mensajes a Electro Toast/notification UI.
2. Configura Refine `auditLogProvider` como thin adapter sobre `audit_events` cuando Audit esté habilitado.
3. Las mutaciones hechas a través de Refine data hooks pueden registrar previousData/newData safe summary; evita duplicar logging en cada pantalla.
4. Application services fuera de Refine (workflow, record transitions, imports) emiten AuditEvent mediante el mismo AuditPort.
5. No loguees password hashes, tokens, secrets, full file contents ni headers de auth.
6. Audit puede deshabilitarse por project/runtime profile si no se necesita; su ausencia no rompe CRUD.
7. Record History consume Audit events de F08; no crea otra revision table.
8. Prueba Create/Update/Delete admin y una mutation externa produciendo eventos coherentes.
9. Actualiza Auth/Policy contracts.
10. Implementa provider/evaluator/use-cases.
11. Conecta route/resource/field/action enforcement.
12. Construye Users/Roles/Simulator UI.
13. Añade deny-path tests además de allow-path.

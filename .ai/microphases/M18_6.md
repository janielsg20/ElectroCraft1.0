# M18.6 — Structured generation workflow y validación canónica

**Fase propietaria:** F18 — Generar con IA — Gemini

## Por qué existe
Los artifacts aplicables deben surgir de una salida tipada, no de texto libre que después se interprete de forma frágil.

## Resultado exacto
Al cerrar esta microfase, **AIGenerationPlan estructurado y validación canónica** está implementada de extremo a extremo para su alcance y produce evidencia real.

## Engine owner
`Vercel AI SDK structured output + Zod + ElectroCraft validators`

## Responsabilidad ElectroCraft
ElectroCraft controla contratos, contexto, UX en español, permisos, validación, borradores, diff y Apply. El proveedor de IA nunca muta el proyecto directamente.

## Ubicación de código obligatoria
- `packages/ai/`
- `apps/studio/src/features/ai/`
- `apps/studio/src/components/ai-elements/`

## Ubicación exacta en la app
Centro muestra primero estado `Planificando…`; Validación enseña el plan y warnings solo en modo avanzado.

## Diseño visual exacto
Beginner ve resumen humano: «Se crearán 1 página, 3 bloques y 1 formulario»; Advanced puede inspeccionar JSON validado.

## Texto y ayuda
Todo texto visible usa i18n español. El título de la sección lleva `CircleHelp`; las opciones técnicas no obvias usan `Info` con HelpRegistry. Nunca mostrar raw provider errors como texto principal.

## Texto visible en español
Generar con IA; Crear; Historial; Contexto; Opciones; Validación; Generar; Aplicar cambios; Guardar como reutilizable.

## Ayuda contextual
Usa HelpRegistry `help.ai`. Si esta microfase introduce un concepto nuevo, añade/actualiza su HelpDescriptor en español. La ayuda crítica no puede vivir solo en un tooltip.

## Precondiciones
- F17 COMPLETADA: los tipos de artifact reutilizable y ElectroCraftExtensionPackage existen.

## Implementación paso por paso
1. Para artifacts críticos usa un workflow determinista: Context -> Plan -> Draft -> Validate -> Preview -> Diff.
2. Define el plan con schema compatible con Google provider; evita unions complejas innecesarias.
3. Ejecuta structured generation a través de AI SDK.
4. Valida output con Zod aunque el provider declare structured success.
5. Resuelve component/data/query/action/route IDs contra registries.
6. Convierte el plan a operaciones sobre AIDraftWorkspace.
7. Ejecuta semantic validators: IDs, refs, slots, data types, route refs, permissions, compatibility.
8. Si el schema requerido supera las limitaciones del provider, divide la generación en sub-artifacts tipados; no vuelvas a Markdown libre como formato de mutación.
9. Produce resumen humano en español desde operaciones validadas.
10. Permite corregir instrucciones y regenerar antes de crear/aplicar el draft.
11. Define request/draft schema antes de prompt/UI.
12. Usa AI SDK para model/tools/structured output y AI Elements para UI estándar.
13. Todas las tools escriben Draft o leen contexto sanitizado.
14. Valida/Preview/Diff antes de Apply.
15. Aplica solo por AIApplyService transaccional.
16. Prueba mock determinista + security + Spanish.

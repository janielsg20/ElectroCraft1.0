# M09.8 — Integrar TanStack Query como runtime query cache

**Fase propietaria:** F09 — Consultas, bindings, listings y filtros

## Por qué existe
Evitar construir un cache/invalidation/loading/retry engine propio para listings y providers.

## Resultado exacto
Al cerrar esta microfase, **Integrar TanStack Query como runtime query cache** debe quedar integrado, persistido/exportable cuando corresponda y cubierto por pruebas. No basta con un tipo, un botón o un placeholder.

## Engine owner
`React Query Builder + TanStack Query + PGlite query adapter`

## Responsabilidad ElectroCraft
Construye únicamente la semántica portable, adapter, configuración, UX y diagnostics que el engine no trae. No dupliques el motor.

## Ubicación visual
Datos > Consultas, Filter UI e Inspector > Data.

## Ubicación de código obligatoria
- `packages/query-builder/`
- `packages/application/src/query/`
- `apps/studio/src/features/queries/`

## Ubicación exacta en la app
No pantalla propia. Cache settings en `Consultas > Avanzado`; runtime state visible en `Vista previa > Debug > Consultas`.

## Diseño visual exacto

## Precondiciones

- El engine owner está encapsulado detrás del adapter correspondiente.

## Implementación línea por línea
1. Define QueryRuntimePort y un adapter Web/React/Native basado en TanStack Query.
2. Query key incluye project/runtime namespace, queryId, normalized params/filter state y relevant data version.
3. Record mutations invalidan keys por contentType/relation/query usage; no `invalidate all` salvo recovery.
4. Listing usa TanStack Query states loading/error/data/isFetching.
5. Refine ya usa TanStack Query en admin; no crees un segundo admin cache.
6. Configura retry/stale policy por query/provider, no hardcoded global.
7. Offline local PGlite/SQLite queries pueden usar staleTime alto/controlled invalidation.
8. Debug Query Trace registra cache hit/refetch reason sin exponer secrets.
9. Actualiza Query/Binding portable definition.
10. Usa RQB solo para condition authoring.
11. Compila a DataSource operation; TanStack Query posee cache en JS runtime.
12. Conecta Listing/Filter/Inspector.
13. Prueba types, invalid rule fail-closed, cache/invalidation.

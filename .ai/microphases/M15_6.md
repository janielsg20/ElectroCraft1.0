## Implementación línea por línea
1. Kanban y Calendar son Admin view modes sobre el mismo DataProvider/content records; no crean databases ni CRUD paralelos.
2. Kanban column = group/status field; drag result ejecuta una normal Refine update/ActionGraph mutation.
3. Studio/Web Kanban usa dnd-kit para drag/drop/sort; no escribas collision/sensor engine propio.
4. Siempre ofrece alternativa keyboard/no-drag `Mover a...` para accesibilidad y como fallback de target.
5. Calendar persiste `CalendarViewSpec` con source/query, id/title/start/end fields, locale/timezone y actions.
6. Studio/Web/React/LAMP/WP client usa FullCalendar Standard adapter únicamente; no introduzcas plugins Premium/Scheduler como requisito core.
7. Native Calendar se mapea posteriormente a react-native-calendars para month/agenda/date selection; resource scheduling avanzado requiere capability explícita.
8. Bulk Actions consumen selected IDs de TanStack/Refine y ActionGraph or Refine mutations; no mutan rows localmente como source of truth.
9. RuntimeDependencyManifest incluye dnd-kit/calendar engine solo cuando esas views existen.
10. Prueba drag + Move-to fallback, Calendar date/event actions, locale/timezone, Bulk permission/error and no Premium dependency.
11. Define AdminScreen/resource semantics.
12. Usa Refine/TanStack para lifecycle/tabla, no reimplementes CRUD.
13. Conecta same DataSource/Permission services.
14. Construye view UI indicada.
15. Prueba CRUD/filters/bulk/permissions/mobile.

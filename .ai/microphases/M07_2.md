# M07.2 — Pantallas: lista, árbol y propiedades

**Fase propietaria:** F07 — Pantallas, navegación y rutas

## Por qué existe
El usuario debe gestionar screens como unidad principal de una app, no como páginas de un datos internos.

## Resultado exacto
Al cerrar esta microfase, **Pantallas: lista, árbol y propiedades** existe como capacidad real, conectada a los contratos de ElectroCraft y demostrada con pruebas. No se acepta placeholder, botón decorativo ni contrato sin consumidor.

## Engine owner
`ElectroCraft Project/Application services`

## Responsabilidad ElectroCraft
ElectroCraft conserva únicamente la semántica portable, la UX española, los adapters, permisos, validación, persistencia y compatibilidad multi-target. El engine OSS conserva la responsabilidad técnica para la que fue elegido.

## Ubicación de código obligatoria
- `packages/domain/src/navigation/`
- `packages/application/src/navigation/`
- `apps/studio/src/features/navigation/`

## Ubicación exacta en la app
`Construir > Pantallas`.

## Diseño visual exacto
Left tree/list 300; main properties/preview summary. Toolbar Buscar/Tipo/Estado/Ordenar/Nueva pantalla. Mobile list->detail.

## Texto visible en español
Pantallas; Nueva pantalla; Abrir en Editor; Duplicar; Ruta; Plantilla; Estado; Pantalla inicial.

## Ayuda contextual
Usa HelpRegistry `help.screens`. El título de pantalla lleva `CircleHelp`; los conceptos técnicos usan `Info` solo cuando aportan contexto real.

## Precondiciones
- Gate de entrada de la fase satisfecho.
- Contratos/engines anteriores verdes.
- No existe una implementación paralela de la misma responsabilidad.

## Implementación paso por paso
1. Implementa screen CRUD vía ProjectService.
2. Screen row muestra icono/nombre/ruta/navigator/status/last edit.
3. Nueva pantalla: Nombre -> Tipo/plantilla -> Ruta -> Navigator -> Crear y abrir.
4. Duplicar genera IDs nuevos y opcional route suggestion.
5. Delete analiza references/actions/navigation antes de permitir.
6. `Abrir en Editor` selecciona document y navega al Screen Composer.
7. Prueba empty state, search, duplicate, usage-guard delete y mobile.
8. Actualiza Navigation/Route contracts primero.
9. Implementa use-case/ref integrity.
10. Construye tree editor español.
11. Añade target compiler contract fixture sin persistir router objects.
12. Prueba params/deep-links/guards/ref rename.

## Estados UI obligatorios
- Inicial.
- Cargando, solo cuando haya espera perceptible.
- Vacío con explicación y CTA.
- Error en español con recuperación.
- Deshabilitado con motivo.
- Guardando/Aplicando cuando corresponda.
- Éxito breve y accionable.

## Responsive
- Desktop: alta densidad sin comprimir la tarea principal.
- Tablet: panel secundario a Sheet/Drawer.
- Mobile: flujo por rutas/pasos; no reducir una UI desktop de tres columnas.

## Accesibilidad
- teclado;
- focus-visible;
- labels persistentes;
- icon-only con aria-label;
- errores anunciables;
- touch targets;
- reduced motion;
- alternativa a drag cuando aplique.

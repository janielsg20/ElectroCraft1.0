# M21.7 — React source exporter con dependency pruning

**Fase propietaria:** F21 — Runtime Web y exportación React/PWA

## Por qué existe
Esta microfase existe para **React source exporter con dependency pruning** dentro de la responsabilidad de `F21`: generar outputs Web/Local con dependencias mínimas. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **React source exporter con dependency pruning** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

## Engine owner
`ElectroCraftExportIR + Web generators`

### Regla
Antes de escribir código, consulta la API pública del engine. Si ya existe la capacidad, úsala. ElectroCraft solo debe aportar canonical mapping, configuración, UX, adapter, target semantics o exportación.

## Precondiciones
- `M21.6` COMPLETADA.
- Engine owner disponible detrás de su adapter.
- No existen errores P0/P1 de la dependencia inmediata.
- Tests existentes están verdes antes de modificar comportamiento.

## Implementación línea por línea
1. Generate source from ElectroCraftExportIR, not from Studio React component tree.
2. Generate route/runtime components, Design Tokens, data adapter, query cache, forms, state, action runtime and assets only if ExportIR requires them.
3. Consult RuntimeDependencyManifest before writing package.json.
4. Never include Puck editor in a normal React export.
5. Never include Rete editor/history; include `rete-engine` only if this app executes ActionGraphs client-side.
6. Include Refine only if generated output contains Administración/Admin runtime.
7. Include Tiptap editor only if generated output allows richtext editing; read-only pages use Tiptap Static Renderer target-specific output.
8. Generate package scripts, README and `.env.example` without secrets.
9. Build fixture must fail if an unnecessary Studio package leaks into dependencies.
10. Congela ExportIR revision.
11. Genera runtime/source mediante shared Web compilers.
12. Genera target-specific package/profile.
13. Ejecuta dependency pruning.
14. Ejecuta install/build/serve/reimport verifier según target.
15. Registra artifact/checksum/report.

1. Usuario/Runtime produce una intención.
2. UI/hook llama al adapter o application service propietario.
3. El engine OSS ejecuta la responsabilidad que le pertenece.
4. ElectroCraft normaliza solo lo que necesita persistencia/portabilidad.
5. Storage o target adapter persiste/ejecuta.
6. Resultado tipado vuelve a UI/runtime.
7. Error/diagnostic permanece visible y reparable.

# M00.8 — POC AI SDK + Gemini: generación de código segura

**Fase propietaria:** F00 — Auditoría de producto, OSS y POCs

## Por qué existe
Gemini será la capacidad AI de ElectroCraft para crear y refinar código de los proyectos. Antes de diseñar la experiencia completa hay que demostrar que puede generar artifacts estructurados para componentes, plugins y secciones sin exponer credenciales ni aplicar cambios automáticamente.

## Resultado exacto
Al cerrar esta microfase debe existir un POC real y verificable que genere código Draft para `component | plugin | section`, con structured output, tool calling limitado, streaming/cancelación, validación de seguridad y gateway server-side.

**No forma parte del alcance:** generación de imágenes.

## Engine owner
AI SDK Core + `@ai-sdk/google` + Zod. `@google/genai` queda limitado a un probe estrecho de Interactions `v1`.

## Responsabilidad ElectroCraft
- contratos portables de artifact de código;
- perfiles lógicos y resolución runtime;
- contexto sanitizado;
- allowlist de tools;
- seguridad/validación;
- Draft/preview antes de cualquier Apply futuro;
- persistencia sin IDs de modelo.

## Ubicación obligatoria
- `experiments/gemini-provider-poc/`
- `.ai/adr/ADR-GEMINI-PROVIDER.md`
- `.ai/evidence/F00/M00.8/`

## Implementación paso por paso
1. Verifica versiones actuales de AI SDK, Google provider, Google GenAI y modelos Gemini adecuados para código.
2. POC A: structured `GenerationPlanPoc` para `component | plugin | section`.
3. POC B: `CodeArtifactPoc` multiarchivo con `entryFile`, lenguaje, contenido, dependencias propuestas, checks y `draftOnly=true`.
4. POC C: tool loop limitado con contexto sanitizado y sin Apply/filesystem/DB/install/deploy/secrets.
5. POC D: streaming de código y manejo de complete/incomplete/error/cancel.
6. POC E: gateway server-side; confirma que ninguna API key llega al cliente ni al artifact generado.
7. POC F: perfiles `Automático | Rápido | Calidad | Código`; IDs actuales solo en metadata de sesión.
8. POC G: Interactions `v1` debe completar una petición real de código a través del adapter estrecho.
9. Valida rutas relativas, traversal, duplicados, `entryFile` y referencias a credenciales antes de aceptar un artifact.
10. Aísla el experimento; no escribas implementación release ni importes producto no aprobado.
11. Define fixtures mínimos reproducibles.
12. Ejecuta APIs OSS reales, typecheck, tests, build, security y live Gemini.
13. Guarda artifacts sanitizados y hashes en evidence.

## Artifacts obligatorios
- POC aislado reproducible;
- ADR del provider;
- baseline de provider/modelos;
- fixtures sanitizados de plan y código;
- evidencia CI estática + live.

## Pruebas obligatorias
1. Structured plan válido/inválido.
2. CodeArtifact válido.
3. Path traversal rechazado.
4. Referencia a secret rechazada.
5. Tool allowed/denied.
6. Gateway no filtra key al client.
7. Offline/provider unavailable.
8. Streaming/cancelación.
9. Generación live real de código.
10. Interactions `v1` live de código.
99. lint.
100. typecheck.
101. test.
102. build.

## Prohibido
- No llamar Gemini desde browser/mobile con una API key de producción.
- No permitir que el modelo escriba PGlite/SQLite/SQL directamente.
- No dar al modelo filesystem write, package install, deploy o Apply directo.
- No ejecutar automáticamente el código generado.
- No convertir IDs de modelos actuales en contratos canónicos permanentes.
- No bloquear M00.8 por generación de imágenes: no es requisito del producto.

## Gate de avance
M00.9 no inicia hasta que static + live code-generation + Interactions estén GREEN y la evidencia de M00.8 esté cerrada.

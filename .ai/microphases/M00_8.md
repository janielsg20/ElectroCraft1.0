# M00.8 — POC AI SDK + Gemini: structured output, tools, imágenes y gateway seguro

**Fase propietaria:** F00 — Auditoría de producto, OSS y POCs

## Por qué existe
Gemini pasa a ser una capacidad central opcional de creación asistida. Antes de diseñar la sección completa hay que demostrar que puede devolver artifacts estructurados, proponer tool calls, generar imágenes y funcionar sin exponer credenciales en el cliente.

## Resultado exacto
Al cerrar esta microfase, **POC Gemini: structured output, tools, imágenes y gateway seguro** debe existir como capacidad real, conectada al sistema y verificable. No se acepta una pantalla decorativa, un tipo vacío ni un botón sin comportamiento.

## Engine owner
`Google GenAI SDK (`@google/genai`) + Gemini Interactions API + Zod`

## Responsabilidad ElectroCraft
ElectroCraft define la experiencia en español, los contratos portables, adapters, seguridad, validación, ayuda contextual y persistencia. El engine OSS conserva la responsabilidad para la que fue elegido.

## Ayuda contextual
Explica que el POC valida la arquitectura; no es una función para el usuario final.
El icono de ayuda usa `CircleHelp` o `Info` de Lucide, tiene `aria-label="Más información"`, tooltip corto y Popover/Sheet con explicación extendida cuando el concepto no sea obvio.

## Precondiciones
- La microfase anterior de la fase está COMPLETADA o el gate de entrada de la fase está satisfecho.
- Las pruebas existentes están verdes.
- Los contratos/engines necesarios están disponibles detrás de adapters.

## Implementación paso por paso
1. Verifica la versión actual de `ai`, `@ai-sdk/google`, `@google/genai`, Gemini models y capacidades oficiales antes de instalar/pinear.
2. POC A: usa AI SDK + Google provider para structured output tipado con Zod sobre un `GenerationPlanPoc`.
3. POC B: define 2 tools con input schema; demuestra loop/tool call con límite de pasos y cancelación.
4. POC C: prueba streaming y manejo de incomplete/error/cancel.
5. POC D: prueba image generation a través de AI SDK si la versión pinned lo soporta con las opciones necesarias.
6. Si POC D no cubre la capacidad Gemini nativa requerida, implementa un `GeminiNativeCapabilityAdapter` mínimo con `@google/genai` solo para esa función.
7. POC E: gateway server-side; confirma mediante bundle/source scan que ninguna API key llega al cliente.
8. POC F: provider/model lógico `Automático|Rápido|Calidad|Imagen` se resuelve dinámicamente y no entra en project canonical data.
9. Documenta qué parte queda delegada a AI SDK y qué parte, si alguna, necesita escape hatch Google.
10. No cierres la POC si obliga a mantener dos stacks completos de AI.
11. Aísla el experimento; no importes implementación de producto no aprobada.
12. Define fixture mínimo reproducible.
13. Ejecuta la API OSS real que se está evaluando.
14. Mide el gap entre OSS y semántica ElectroCraft.
15. Documenta decisión/limitación/licencia/API usada.
16. Guarda logs/artifacts en evidence.

## Estados UI obligatorios
- `Inicial`: contexto listo, todavía sin acción.
- `Cargando`: solo si existe trabajo perceptible.
- `Vacío`: explica qué puede hacer el usuario y ofrece CTA.
- `Error`: mensaje humano en español + Retry/Reparar cuando proceda.
- `Deshabilitado`: explica por qué no se puede ejecutar.
- `Guardando/Aplicando`: progreso no bloqueante cuando sea posible.
- `Completado`: confirmación breve y siguiente acción útil.

## Responsive
- Desktop >=1280: conserva alta densidad y paneles definidos.
- Laptop: colapsa tooling secundario antes que el área principal.
- Tablet: paneles secundarios -> Sheet/Drawer.
- Mobile: flujo por pasos/pantallas; no comprimas tres paneles en una sola vista.

## Accesibilidad

- errores anunciables;

# M18.1 — Contratos de generación y AIDraftWorkspace sobre Vercel AI SDK

**Fase propietaria:** F18 — Generar con IA — Gemini

## Por qué existe
Sin contratos claros la IA terminaría escribiendo modelos ad hoc o estado del proveedor dentro del proyecto.

## Resultado exacto
Al cerrar esta microfase, **Contratos AIProvider, AIGenerationRequest y AIDraftWorkspace** está implementada de extremo a extremo para su alcance y produce evidencia real.

## Engine owner
`Vercel AI SDK Core + Zod + ElectroCraft AI contracts`

## Responsabilidad ElectroCraft
ElectroCraft controla contratos, contexto, UX en español, permisos, validación, borradores, diff y Apply. El proveedor de IA nunca muta el proyecto directamente.

## Ubicación de código obligatoria
- `packages/ai/`
- `apps/studio/src/features/ai/`
- `apps/studio/src/components/ai-elements/`

## Ubicación exacta en la app
No UI nueva todavía; tipos en packages/ai-core. `Generar con IA` permanece feature-gated hasta M18.4.

## Diseño visual exacto
No inventar cards ni pantallas; esta microfase es contract-first.

## Texto y ayuda
Todo texto visible usa i18n español. El título de la sección lleva `CircleHelp`; las opciones técnicas no obvias usan `Info` con HelpRegistry. Nunca mostrar raw provider errors como texto principal.

## Texto visible en español
Generar con IA; Crear; Historial; Contexto; Opciones; Validación; Generar; Aplicar cambios; Guardar como reutilizable.

## Ayuda contextual
Usa HelpRegistry `help.ai`. Si esta microfase introduce un concepto nuevo, añade/actualiza su HelpDescriptor en español. La ayuda crítica no puede vivir solo en un tooltip.

## Precondiciones
- F17 COMPLETADA: los tipos de artifact reutilizable y ElectroCraftExtensionPackage existen.
- F00 POC Gemini aprobado.
- i18n/HelpRegistry/AppShell disponibles.
- provider secrets fuera del cliente.

## Implementación paso por paso
1. Elimina la abstracción genérica `AI SDK model/provider interface` si todavía aparece en código/docs.
2. Usa los tipos/provider interfaces de AI SDK como boundary de model invocation; no se persisten.
3. Define `AIGenerationRequest` con artifactKind, instruction, contextRefs, logicalModelProfile, targets, reuseIntent, toolPolicy, privacyPolicy y baseRevision.
4. Define `AIGenerationPlan`, `AIArtifactDraft`, `AIChangeOperation`, `AIValidationReport`, `AIOrigin` y statuses.
5. Define `AIDraftWorkspacePort` separado de ProjectRepository; Draft nunca escribe canonical objects.
6. Define `AIApplyService` como application service invocado solo desde UI.
7. Define `AIModelProfileResolver` para Automático/Rápido/Calidad/Imagen.
8. Define versioned Zod schemas para request/plan/draft.
9. Clasifica provider/runtime data como transient or Studio-only, nunca project canonical.
10. Añade contract tests que impidan que AI SDK response/tool objects aparezcan en ElectroCraftProjectDefinition.
11. Define request/draft schema antes de prompt/UI.
12. Usa AI SDK para model/tools/structured output y AI Elements para UI estándar.
13. Todas las tools escriben Draft o leen contexto sanitizado.
14. Valida/Preview/Diff antes de Apply.
15. Aplica solo por AIApplyService transaccional.
16. Prueba mock determinista + security + Spanish.

# M15.1 — AdminDataProviderAdapter + Refine bootstrap

**Fase propietaria:** F15 — Administración visual y DataViews

## Por qué existe
Esta microfase existe para **ElectroCraftDataProvider + Refine bootstrap** dentro de la responsabilidad de `F15`: resolver Administración con Refine/TanStack. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **ElectroCraftDataProvider + Refine bootstrap** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

## Engine owner
`Refine + TanStack + RHF`

### Regla
Antes de escribir código, consulta la API pública del engine. Si ya existe la capacidad, úsala. ElectroCraft solo debe aportar canonical mapping, configuración, UX, adapter, target semantics o exportación.

## Precondiciones
- Gate de entrada de `F15` satisfecho.
- Engine owner disponible detrás de su adapter.
- No existen errores P0/P1 de la dependencia inmediata.
- Tests existentes están verdes antes de modificar comportamiento.

## Implementación línea por línea
1. Implementa el Refine DataProvider como adapter sobre ElectroCraft DataSource/Query services.
2. No conviertas DataProvider en la API general de una app normal.
3. Map resource -> DataModel/DataSource resource.
4. Implement getList/getOne/create/update/delete/createMany según capability de source.
5. Pasa filtros/sort/pagination por Query compiler seguro.
6. Integra permission/audit/notification adapters.
7. TanStack Query lifecycle de Refine se mantiene dentro de Administración.
8. Prueba internal source, REST source read-only, unsupported mutation y permission denial.
9. Define AdminScreen/resource semantics.
10. Usa Refine/TanStack para lifecycle/tabla, no reimplementes CRUD.
11. Conecta same DataSource/Permission services.
12. Construye view UI indicada.
13. Prueba CRUD/filters/bulk/permissions/mobile.

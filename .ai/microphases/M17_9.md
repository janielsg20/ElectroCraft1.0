# M17.9 — ElectroCraftExtensionPackage: plugins/extensiones reutilizables y seguros

**Fase propietaria:** F17 — Extensiones, Kits de App y plantillas de proyecto

## Por qué existe
La nueva generación con IA debe poder crear plugins/extensiones reutilizables sin introducir ejecución arbitraria directa. Antes de la fase IA se necesita un formato instalable y auditable.

## Resultado exacto
Al cerrar esta microfase, **ElectroCraftExtensionPackage: plugins/extensiones reutilizables y seguros** debe existir como capacidad real, conectada al sistema y verificable. No se acepta una pantalla decorativa, un tipo vacío ni un botón sin comportamiento.

## Engine owner
`Electro registries + existing canonical models + package validator`

## Responsabilidad ElectroCraft
ElectroCraft define la experiencia en español, los contratos portables, adapters, seguridad, validación, ayuda contextual y persistencia. El engine OSS conserva la responsabilidad para la que fue elegido.

## Ayuda contextual
CircleHelp en título explica: «Una extensión añade contenido o capacidades reutilizables a ElectroCraft. Las extensiones declarativas no ejecutan código arbitrario; las que contienen código requieren revisión y pruebas antes de instalarse.»
El icono de ayuda usa `CircleHelp` o `Info` de Lucide, tiene `aria-label="Más información"`, tooltip corto y Popover/Sheet con explicación extendida cuando el concepto no sea obvio.

- La microfase anterior de la fase está COMPLETADA o el gate de entrada de la fase está satisfecho.

- Los contratos/engines necesarios están disponibles detrás de adapters.

## Implementación paso por paso
1. Define `ElectroCraftExtensionManifest` con id, nombre, versión, descripción, autor, compatibility, capabilities, permissions, dependencies y artifact refs.
2. Define `ElectroCraftExtensionPackage` declarativo capaz de incluir Blocks, Presets, Templates, Themes, Form Documents, Queries, ActionGraphs, Admin Screens, Schema additions, Help/i18n entries y Blueprint fragments.
3. Las definiciones se instalan usando los registries/services públicos existentes; no crea un segundo plugin runtime.
4. Define lifecycle validate -> preview impact -> resolve conflicts -> install transaction -> enable/disable -> uninstall with usage analysis.
5. Una extensión declarativa no contiene `eval`, scripts inline ni módulos JS arbitrarios.
6. Define `codeModules` únicamente como fuente en cuarentena `draft-code` para casos avanzados; no se ejecuta ni instala hasta security review, lint/typecheck/test/build y aceptación explícita.
7. Extensiones generadas con IA se guardan primero como `Borrador` y muestran origen/model/session metadata no sensible.
8. Implementa permisos/capabilities declarativos y target compatibility por cada artifact incluido.
9. Uninstall no borra records/user data sin un plan de cleanup explícito.
10. Prueba instalación selectiva, conflicto, disable/enable, uninstall bloqueado por usage y declarative package round-trip.
11. Valida manifest/version/dependencies/permissions.
12. Instala artifacts mediante services existentes.
13. No crees runtime de plugin paralelo.
14. Conecta Catalog/Install/Conflict UI.
15. Prueba install/upgrade/uninstall/code quarantine.

## Estados UI obligatorios
- `Inicial`: contexto listo, todavía sin acción.
- `Cargando`: solo si existe trabajo perceptible.
- `Vacío`: explica qué puede hacer el usuario y ofrece CTA.
- `Error`: mensaje humano en español + Retry/Reparar cuando proceda.
- `Deshabilitado`: explica por qué no se puede ejecutar.
- `Guardando/Aplicando`: progreso no bloqueante cuando sea posible.
- `Completado`: confirmación breve y siguiente acción útil.

## Responsive
- Desktop >=1280: conserva alta densidad y paneles definidos.
- Laptop: colapsa tooling secundario antes que el área principal.
- Tablet: paneles secundarios -> Sheet/Drawer.
- Mobile: flujo por pasos/pantallas; no comprimas tres paneles en una sola vista.

## Accesibilidad
- teclado completo;
- focus-visible;
- labels persistentes;
- icon-only con aria-label;
- errores anunciables;
- touch targets adecuados;
- reduced motion;
- alternativa a drag/drop si existe.

## Pruebas obligatorias
1. Declarative install/disable/uninstall.
2. Conflict resolver.
3. Permission/capability validation.
4. Draft-code cannot execute.
5. Mobile management flow.
99. Ejecuta lint.

## Prohibido
- No crear un runtime de plugins separado de los registries existentes.
- No ejecutar código generado por IA automáticamente.
- No incluir secretos en el package.

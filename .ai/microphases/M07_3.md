# M07.3 — Editor visual orientado a Pantallas

**Fase propietaria:** F07 — Pantallas, navegación y rutas

## Por qué existe
El editor debe hablar de una app y sus pantallas, no de una página web como supuesto único.

## Resultado exacto
Al cerrar esta microfase, **Editor visual orientado a Pantallas** existe como capacidad real, conectada a los contratos de ElectroCraft y demostrada con pruebas. No se acepta placeholder, botón decorativo ni contrato sin consumidor.

## Engine owner
`Puck + Screen context`

## Responsabilidad ElectroCraft
ElectroCraft conserva únicamente la semántica portable, la UX española, los adapters, permisos, validación, persistencia y compatibilidad multi-target. El engine OSS conserva la responsabilidad técnica para la que fue elegido.

## Ubicación de código obligatoria
- `packages/domain/src/navigation/`
- `packages/application/src/navigation/`
- `apps/studio/src/features/navigation/`

## Ubicación exacta en la app
`Construir > Editor`.

## Diseño visual exacto
Context tabs `Componentes | Pantallas | Capas`; Canvas central; Inspector. Topbar selector Pantalla + Plataforma + Breakpoint.

## Texto visible en español
Componentes; Pantallas; Capas; Lienzo; Pantalla; Plataforma; Dispositivo.

## Ayuda contextual
Usa HelpRegistry `help.editor.screens`. El título de pantalla lleva `CircleHelp`; los conceptos técnicos usan `Info` solo cuando aportan contexto real.

## Precondiciones
- Gate de entrada de la fase satisfecho.
- Contratos/engines anteriores verdes.
- No existe una implementación paralela de la misma responsabilidad.

## Implementación paso por paso
1. Implementa el tab `Pantallas` como selector/contexto del Screen Composer; cualquier import legacy que use `Páginas` se migra fuera de la UI release.
2. El document selector lista screens/forms/admin screens según workspace context.
3. Canvas frame puede simular Web/Desktop/Tablet/Mobile sin cambiar canonical screen.
4. Breadcrumb muestra App > Pantalla > Node.
5. Component insert/selection sigue Puck.
6. Prueba switch screen sin mezclar history stacks y Spanish labels.
7. Actualiza Navigation/Route contracts primero.
8. Implementa use-case/ref integrity.
9. Construye tree editor español.
10. Añade target compiler contract fixture sin persistir router objects.
11. Prueba params/deep-links/guards/ref rename.

## Artefactos obligatorios al cerrar
- `Screen-aware Editor shell`
- `editor screen switching tests`

## Estados UI obligatorios
- Inicial.
- Cargando, solo cuando haya espera perceptible.
- Vacío con explicación y CTA.
- Error en español con recuperación.
- Deshabilitado con motivo.
- Guardando/Aplicando cuando corresponda.
- Éxito breve y accionable.

## Responsive
- Desktop: alta densidad sin comprimir la tarea principal.
- Tablet: panel secundario a Sheet/Drawer.
- Mobile: flujo por rutas/pasos; no reducir una UI desktop de tres columnas.

## Accesibilidad
- teclado;
- focus-visible;
- labels persistentes;
- icon-only con aria-label;
- errores anunciables;
- touch targets;
- reduced motion;
- alternativa a drag cuando aplique.

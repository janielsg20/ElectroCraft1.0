# M13.7 — Añadir Domain Event Triggers y automatización

**Fase propietaria:** F13 — Acciones, workflows y automatizaciones

## Por qué existe
Implementar automatización sin crear un scheduler/workflow subsystem distinto a Rete.

## Resultado exacto
Al cerrar esta microfase, **Añadir Domain Event Triggers y automatización** debe quedar integrado, persistido/exportable cuando corresponda y cubierto por pruebas. No basta con un tipo, un botón o un placeholder.

## Engine owner
`Rete + rete-engine + rete-history-plugin + HTTP providers`

## Responsabilidad ElectroCraft
Construye únicamente la semántica portable, adapter, configuración, UX y diagnostics que el engine no trae. No dupliques el motor.

## Implementación línea por línea
1. Define trigger nodes OnRecordCreated, OnRecordUpdated, OnRecordDeleted, OnStatusChanged, OnUserRegistered y OnFormSubmitted.
2. Application services publican eventos tipados después del commit exitoso, no antes.
3. AutomationDispatcher localiza ActionGraphs suscritos y los ejecuta mediante Rete runtime adapter.
4. Evita loops infinitos con correlationId/depth/max-runs policy.
5. Execution failures generan trace/audit y retry policy explícita; no revierten automáticamente una mutación ya committed salvo transaction design específico.
6. Server exporters compilan estos triggers a hooks/listeners del target.
7. Native background automation solo se habilita si target capability lo soporta.
8. Prueba record update -> automation -> secondary update con loop guard.
9. Actualiza ActionGraph/node definition.
10. Mapea a Rete editor/runtime sin persistir classes.
11. Implementa node service/provider adapter.
12. Define target compiler semantics.
13. Prueba graph/history/runtime/loop/error.

# M10.1 — Media metadata y OPFS adapter

**Fase propietaria:** F10 — Medios y Rich Text

## Por qué existe
Esta microfase existe para **Media metadata y OPFS adapter** dentro de la responsabilidad de `F10`: gestionar media/richtext. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **Media metadata y OPFS adapter** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

## Engine owner
`Tiptap + OPFS/PGlite`

### Regla
Antes de escribir código, consulta la API pública del engine. Si ya existe la capacidad, úsala. ElectroCraft solo debe aportar canonical mapping, configuración, UX, adapter, target semantics o exportación.

## Precondiciones
- Gate de entrada de `F10` satisfecho.

- No existen errores P0/P1 de la dependencia inmediata.
- Tests existentes están verdes antes de modificar comportamiento.

## Implementación línea por línea
1. Define `MediaBlobStorePort`; media metadata permanece en PGlite.
2. Implementa OPFS como blob store preferido cuando el browser lo soporte correctamente.
3. Implementa fallback local IndexedDB Blob store para navegadores/contexts donde OPFS no esté disponible o falle el capability test; esto NO es un segundo ProjectRepository.
4. Asset ID estable es la clave; filename es metadata y nunca una ruta confiable.
5. `media_metadata` guarda checksum, MIME real, filename seguro, size, dimensions/duration, tags/folder, alt, storage backend y usage refs.
6. Upload primero valida límites/MIME, escribe bytes, confirma checksum y luego registra metadata transaccionalmente; si metadata falla limpia orphan bytes.
7. Read devuelve Blob/stream/object URL con lifecycle controlado; no copies bytes para cada usage.
8. Delete verifica references y borra metadata/bytes coherentemente.
9. Test OPFS path, fallback path, large asset, reopen, orphan cleanup y duplicate reuse.
10. Define portable media/rich-text payload.
11. Implementa MediaBlobStore o Tiptap adapter; no segundo engine.
12. Conecta Studio UI/field.
13. Implementa target-safe read rendering.
14. Prueba storage/security/round-trip.

# M15.8 — Quick Edit y Inline Mutation con Refine

**Fase propietaria:** F15 — Administración visual y DataViews

## Por qué existe
Recuperar quick edit del backend usando mutaciones Refine/RHF, no un segundo CRUD.

## Resultado exacto
Al cerrar esta microfase, **Quick Edit y Inline Mutation con Refine** debe quedar integrado, persistido/exportable cuando corresponda y cubierto por pruebas. No basta con un tipo, un botón o un placeholder.

## Engine owner
`Refine Core + TanStack Table + RHF`

## Responsabilidad ElectroCraft
Construye únicamente la semántica portable, adapter, configuración, UX y diagnostics que el engine no trae. No dupliques el motor.

## Ubicación visual
App > Administración.

## Ubicación de código obligatoria
- `packages/admin-refine/`
- `apps/studio/src/features/administration/`

## Ubicación exacta en la app
`Administración > Lista`: click/edit control on eligible cell; field config under screen columns.

## Diseño visual exacto
Inline editor inside cell with Save/Cancel/error; complex fields open Sheet/Edit screen.

## Texto visible en español
Administración; Dashboard; Lista; Crear; Editar; Detalle; Vista guardada; Importar CSV; Exportar CSV; Edición rápida.

## Ayuda contextual
Usa HelpRegistry `help.backend`. Si esta microfase introduce un concepto nuevo, añade/actualiza su HelpDescriptor en español. La ayuda crítica no puede vivir solo en un tooltip.

## Precondiciones
- La microfase anterior de la fase está COMPLETADA o la dependencia está documentada como ya disponible.
- Los contratos canónicos necesarios existen.
- El engine owner está encapsulado detrás del adapter correspondiente.

## Implementación línea por línea
1. AdminScreen/List config permite marcar fields quickEditable.
2. TanStack cell activa editor inline Electro solo para fields permitidos y simples.
3. Usa Refine `useUpdate`/data mutation pipeline para guardar; no escribe repository directamente.
4. Validation reutiliza Zod/FieldRegistry.
5. Optimistic update solo si mutation policy lo permite; failure revierte cell y muestra error.
6. Permission evaluator verifica field editability antes de mostrar y antes de mutation.
7. Complex/relation/richtext fields abren Edit screen/Sheet en lugar de inline editor.
8. Prueba success/error/permission y SavedView no se contamina con edit state.
9. Define AdminScreen/resource semantics.
10. Usa Refine/TanStack para lifecycle/tabla, no reimplementes CRUD.
11. Conecta same DataSource/Permission services.
12. Construye view UI indicada.
13. Prueba CRUD/filters/bulk/permissions/mobile.

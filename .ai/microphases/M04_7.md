# M04.7 — Workspace preferences

**Fase propietaria:** F04 — Persistencia local, proyectos y revisiones

## Por qué existe
Esta microfase existe para **Workspace preferences** dentro de la responsabilidad de `F04`: persistir incrementalmente y gestionar proyectos/revisiones. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **Workspace preferences** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

## Engine owner
`PGlite/Drizzle + OPFS`

### Regla
Antes de escribir código, consulta la API pública del engine. Si ya existe la capacidad, úsala. ElectroCraft solo debe aportar canonical mapping, configuración, UX, adapter, target semantics o exportación.

## Implementación línea por línea
1. Guarda preferencias Studio-only por usuario/device y, cuando corresponda, override por project workspace.
2. Incluye: sidebar side `left|right`, expanded/collapsed, width, display `icons|text|icons+text`, group order, visible panels, Context/Inspector widths, last tabs/document y saved workspace layouts.
3. El layout default sigue siendo Sidebar izquierda 240/64, Topbar 52, Context 288, Canvas flex, Inspector 320 y Status 26.
4. Reordenar secciones cambia solo presentación; IDs/routes de módulos no cambian.
5. Clamp panel widths y side/layout choices por viewport; en Tablet/Mobile aplica adaptive layout aunque el usuario guardara desktop panels simultáneos.
6. Settings > Workspace permite Save Layout, Rename, Apply, Delete custom layout y Restore Default.
7. Preferences no aparecen en ElectroCraftExportIR/professionalStudio.
8. Sincroniza cambios entre tabs del mismo Studio mediante storage/event layer, no mediante project content mutation.
9. Prueba left/right, icons/text/both, reordered groups, saved layouts, reopen y mobile clamp.
10. Cambia primero repository/service contract.
11. Implementa Drizzle/PGlite transaction/migration.
12. Conecta use-case; UI nunca llama PGlite directamente.
13. Añade save/reopen/recovery behavior.
14. Añade migration/integration fixture.

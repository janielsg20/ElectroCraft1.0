# M26.1 — Descriptor WordPress y configuración del target

**Fase propietaria:** F26 — Exportación WordPress Block Theme + Companion Plugin

## Por qué existe
WordPress debe existir en TargetRegistry con el mismo estatus de producto, análisis y evidencia que el resto.

## Resultado exacto
Al cerrar esta microfase, **Descriptor WordPress y configuración del target** funciona de forma observable dentro del target correspondiente y pasa su gate. No se acepta un archivo generado sin validación ni una opción visual sin compiler/runtime real.

## Engine owner
`WordPress native platform metadata + ExportTargetRegistry`

## Responsabilidad ElectroCraft
ElectroCraft implementa únicamente el mapping desde modelos canónicos, la UX española, configuración, validación, diagnósticos, seguridad, compilación y evidencia. El framework/SDK target conserva routing/runtime/API behavior que ya ofrece.

## Ubicación de código obligatoria
- `packages/export-wordpress/`
- `packages/export-core/`
- `fixtures/wordpress/`

## Ubicación exacta en la app
`Publicar > Exportar > WordPress`.

## Diseño visual exacto
Export Center estándar. Config: Tema, Plugin, Datos, Rutas, Administración, Compatibilidad, Paquetes. Panel de resultado muestra dos ZIP obligatorios cuando aplica.

## Texto visible en español
WordPress; Tema de bloques; Plugin complementario; Datos; Administración; Analizar; Generar.

## Ayuda contextual
Usa HelpRegistry `help.export.wordpress`. El H1 usa `CircleHelp`; las opciones técnicas muestran Info solo cuando explican una decisión o requisito del target.

## Precondiciones
- Gate de la fase anterior satisfecho.
- ExportIR/TargetRegistry/Capability Analyzer disponibles.
- Tests existentes verdes antes de modificar el target.
- No existe un exporter paralelo para la misma responsabilidad.

## Implementación paso por paso
1. Registra `wordpress` como Core target.
2. Config schema: namespace/prefix, theme slug/name, plugin slug/name, minimum WP/PHP baseline verified at implementation, data strategy, include demo data toggle.
3. Define artifact kinds Theme ZIP + Companion Plugin ZIP + report.
4. Define toolchain verifier based on wp-env/approved current test environment.
5. No external page-builder dependency.
6. Add HelpDescriptor and target parity tests.
7. Primero ejecuta mapping ladder a APIs WordPress nativas.
8. Genera Block Theme para diseño y Companion Plugin para comportamiento/datos.
9. Usa theme.json/blocks/CPT/tax/meta/options/REST/users/media antes de custom code/tables.
10. Ejecuta wp-env clean install/lifecycle/security tests.
11. Verifica Theme ZIP + Plugin ZIP checksums.

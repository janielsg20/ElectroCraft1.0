# M02.3 — Definir ownership de Data Sources, Data Models, Queries y Forms

**Fase propietaria:** F02 — Modelo canónico de App y ownership

## Por qué existe
Esta microfase existe para **Definir ownership de Schema, Query y Form Documents** dentro de la responsabilidad de `F02`: definir ownership/modelos portables mínimos. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **Definir ownership de Schema, Query y Form Documents** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

`Zod boundaries`

## Implementación línea por línea
1. Define ownership: DataSourceDefinition describe origen/conector; no contiene secrets.
2. Define ElectroCraftDataSchema/DataModel metadata para la fuente interna.
3. Define QueryDefinition como operación portable sobre una DataSource.
4. Define Form como ElectroCraftDocument kind=form + formMeta; no Form tree paralelo.
5. Define Binding refs a DataSource/Query/State/Route/User/Form/Action output.
6. Define que Refine DataProvider es adapter de Administración, no canonical data model.
7. Define ConnectorRegistry como application registry, no copiado al proyecto.
8. Añade type/reference validators y ownership tests.
9. Define/actualiza schema TypeScript/Zod en domain/contracts.
10. Añade referencias IDs, versioning y validation.
11. Implementa serializer/migration si el shape persistido cambia.
12. Añade application-facing types sin importar engines.
13. Añade fixture round-trip y boundary test.

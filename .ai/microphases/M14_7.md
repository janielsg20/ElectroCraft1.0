# M14.7 — Anti-bot opcional y acciones Email/Webhook

**Fase propietaria:** F14 — Formularios

## Por qué existe
Preservar CAPTCHA/email/webhooks sin introducir dependencia SaaS obligatoria.

## Resultado exacto
Al cerrar esta microfase, **Anti-bot opcional y acciones Email/Webhook** debe quedar integrado, persistido/exportable cuando corresponda y cubierto por pruebas. No basta con un tipo, un botón o un placeholder.

## Engine owner
`React Hook Form + Zod + ElectroCraftActionGraph`

## Responsabilidad ElectroCraft
Construye únicamente la semántica portable, adapter, configuración, UX y diagnostics que el engine no trae. No dupliques el motor.

## Ubicación visual
Lógica > Formularios / visual Form document.

## Ubicación de código obligatoria
- `packages/forms/`
- `apps/studio/src/features/forms/`

## Ubicación exacta en la app
`Formulario > Configuración > Seguridad`.

## Diseño visual exacto
Honeypot/min-time/provider status controls; target-specific CSRF explanation via Info.

## Texto visible en español
Formularios; Nuevo formulario; Campo; Validación; Condiciones; Acción al enviar; Mensajes; Seguridad.

## Ayuda contextual
Usa HelpRegistry `help.forms`. Si esta microfase introduce un concepto nuevo, añade/actualiza su HelpDescriptor en español. La ayuda crítica no puede vivir solo en un tooltip.

## Precondiciones
- La microfase anterior de la fase está COMPLETADA o la dependencia está documentada como ya disponible.
- Los contratos canónicos necesarios existen.
- El engine owner está encapsulado detrás del adapter correspondiente.

## Implementación línea por línea
1. Core anti-bot local ofrece honeypot + minimum-submit-time/rate policy where applicable; no lo presentes como CAPTCHA fuerte.
2. Define `AntiBotProviderPort` para Turnstile/reCAPTCHA/otro adapter opcional futuro; si no está configurado, no bloquea forms que no lo requieran.
3. FormDefinition puede marcar antiBot requirement/capability.
4. Email/Webhook actions son nodes del ActionGraph y reutilizan providers de F13.
5. CSRF se activa en server exports (LAMP/WP) mediante sus adapters; no inventes CSRF token para una pure local client-only form.
6. UI Form Settings explica qué protección existe por target.
7. Compatibility Analyzer bloquea target si form exige provider no disponible.
8. Prueba honeypot, server CSRF fixture y missing provider blocker.
9. Mantén Form como ElectroCraftDocument + metadata.
10. Implementa RHF/Zod adapter para Studio/JS targets.
11. Conecta Data/Action submit.
12. Define portable validation constraints para server compilers.
13. Prueba conditional/multistep/error/submit.

## Artefactos obligatorios al cerrar
- `AntiBotProviderPort`
- `Form security settings`
- `anti-bot/export tests`

## Estados y errores
- Define empty/loading/error/disabled/blocked cuando tengan sentido.
- Un caso unsupported nunca se convierte silenciosamente en success.
- Diagnostics deben incluir código, ubicación, causa y acción sugerida.

## Responsive y accesibilidad si toca UI
- Desktop high-density sin overflow.
- Tablet usa Sheet/Drawer para tooling secundario.
- Mobile usa route/card/bottom-sheet, no desktop comprimido.
- Keyboard/focus-visible/aria-label.
- Alternative a DnD/gestos.

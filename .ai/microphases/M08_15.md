# M08.15 — Configuración global, perfiles y almacenes internos

**Fase propietaria:** F08 — Fuentes de datos, modelos internos, registros y conectores

## Por qué existe
Preservar equivalentes a option pages/profiles/data stores reutilizando Modelo de datoss y permisos.

## Resultado exacto
Al cerrar esta microfase, **Modelar Global Options, Profiles y Data Stores sin nuevos engines** debe quedar integrado, persistido/exportable cuando corresponda y cubierto por pruebas. No basta con un tipo, un botón o un placeholder.

## Engine owner
`PGlite/Drizzle + ElectroCraftDataSchema`

## Responsabilidad ElectroCraft
Construye únicamente la semántica portable, adapter, configuración, UX y diagnostics que el engine no trae. No dupliques el motor.

## Ubicación visual
Datos > Modelos/Contenido/Taxonomías/Relaciones.

## Ubicación de código obligatoria
- `packages/connectors/`
- `packages/data-web/`
- `packages/domain/src/data/`
- `apps/studio/src/features/data/`

## Ubicación exacta en la app

## Diseño visual exacto
Preset cards con explicación; al crear se abre Model detail normal.

## Texto visible en español
Modelos; Campos; Taxonomías; Relaciones; Contenido; Workflow; Historial; Opciones globales; Perfil de usuario.

## Ayuda contextual
Usa HelpRegistry `help.content.models`. Si esta microfase introduce un concepto nuevo, añade/actualiza su HelpDescriptor en español. La ayuda crítica no puede vivir solo en un tooltip.

## Precondiciones
- La microfase anterior de la fase está COMPLETADA o la dependencia está documentada como ya disponible.
- Los contratos canónicos necesarios existen.
- El engine owner está encapsulado detrás del adapter correspondiente.

## Implementación línea por línea
1. Implementa `singleton`/`internal` flags en ElectroCraftDataModel metadata.
2. Global Options = ElectroCraftDataModel singleton con un único record y sin archive público.
3. User Profile = ElectroCraftDataModel/field group linked one-to-one to userId o relation user; no nuevo profile database engine.
4. Internal Data Store = private ElectroCraftDataModel/list con admin visibility configurable.
5. Flexible Content se expresa mediante Group/Repeater/block-like field structures existentes.
6. Todos usan RecordService, FieldRegistry, permissions, Query/Binding y exporters existentes.
7. UI Model Builder ofrece presets `Global Options`, `User Profile`, `Internal Data Store` que crean configuración normal, no special-case hardcode.
8. Prueba export mapping a React/LAMP/WordPress strategy.
9. Define DataSource/DataModel contract/capabilities.
10. Implementa adapter/repository behind ConnectorRegistry.
11. Resuelve secrets por SecretRef/Gateway.
12. Construye Data UI/Explorer/Model UI indicada.
13. Prueba schema/capabilities/CRUD/error/security.

## Estados y errores
- Define empty/loading/error/disabled/blocked cuando tengan sentido.
- Un caso unsupported nunca se convierte silenciosamente en success.
- Diagnostics deben incluir código, ubicación, causa y acción sugerida.

## Responsive y accesibilidad si toca UI
- Desktop high-density sin overflow.
- Tablet usa Sheet/Drawer para tooling secundario.
- Mobile usa route/card/bottom-sheet, no desktop comprimido.
- Keyboard/focus-visible/aria-label.
- Alternative a DnD/gestos.

5. E2E si existe UI.

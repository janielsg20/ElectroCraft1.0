# M04.6 — Import/Backup/Restore

**Fase propietaria:** F04 — Persistencia local, proyectos y revisiones

## Por qué existe
Esta microfase existe para **Import/Backup/Restore** dentro de la responsabilidad de `F04`: persistir incrementalmente y gestionar proyectos/revisiones. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **Import/Backup/Restore** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

## Engine owner
`PGlite/Drizzle + OPFS`

### Regla
Antes de escribir código, consulta la API pública del engine. Si ya existe la capacidad, úsala. ElectroCraft solo debe aportar canonical mapping, configuración, UX, adapter, target semantics o exportación.

## Precondiciones
- `M04.5` COMPLETADA.
- Engine owner disponible detrás de su adapter.
- No existen errores P0/P1 de la dependencia inmediata.
- Tests existentes están verdes antes de modificar comportamiento.

## Implementación línea por línea
1. Backup package manifest + canonical snapshot + media refs/files.
2. Import valida manifest/version/checksum antes de DB write.
3. Collision -> import as copy o estrategia explícita.
4. Restore crea snapshot de seguridad antes de reemplazar.
5. Round-trip test.
6. Cambia primero repository/service contract.
7. Implementa Drizzle/PGlite transaction/migration.
8. Conecta use-case; UI nunca llama PGlite directamente.
9. Añade save/reopen/recovery behavior.
10. Añade migration/integration fixture.

## Artefactos obligatorios al cerrar
- `repository/service/DB migration correspondiente`
- `persistence/reopen/recovery integration test`

## Flujo de datos obligatorio
1. Usuario/Runtime produce una intención.
2. UI/hook llama al adapter o application service propietario.
3. El engine OSS ejecuta la responsabilidad que le pertenece.
4. ElectroCraft normaliza solo lo que necesita persistencia/portabilidad.
5. Storage o target adapter persiste/ejecuta.
6. Resultado tipado vuelve a UI/runtime.
7. Error/diagnostic permanece visible y reparable.

# M14.5 — Submit ActionGraph integration

**Fase propietaria:** F14 — Formularios

## Por qué existe
Esta microfase existe para **Submit ActionGraph integration** dentro de la responsabilidad de `F14`: resolver Forms con RHF/Zod/ActionGraph. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **Submit ActionGraph integration** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

## Engine owner
`RHF + Zod + Puck form composition`

## Implementación línea por línea
1. `ElectroCraftDocument.kind="form"` obtiene `submitGraphRef` desde `formMeta`; no existe ElectroFormDefinition paralela.
2. RHF `handleSubmit` valida primero Zod y crea un typed `FormContext`.
3. Pasa FormContext al ActionGraph trigger OnFormSubmitted/OnSubmit.
4. Built-in UX presets CreateRecord/UpdateRecord/Login/Register/Upload/Navigate/Message/Email/Webhook solo crean/configuran ActionGraph nodes; no ejecutan lógica aparte.
5. Upload usa Media adapter de F10 y devuelve MediaAsset refs.
6. Login/Register usa AuthProvider de F12.
7. State updates usan Zustand adapter de F11.
8. Success/error outputs del graph actualizan el Form runtime status; los Text presets de Status lo muestran con aria-live y optional navigation.
9. No side effects desde render/effects de mount salvo trigger explícito.
10. Prueba Create record + Media upload + Toast/Navigate usando el mismo Form Document guardado.
11. Mantén Form como ElectroCraftDocument + metadata.
12. Implementa RHF/Zod adapter para Studio/JS targets.
13. Conecta Data/Action submit.
14. Define portable validation constraints para server compilers.
15. Prueba conditional/multistep/error/submit.

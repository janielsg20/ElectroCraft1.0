# M06.6 — Breadcrumbs y context actions

**Fase propietaria:** F06 — Layout, responsive y edición avanzada

## Por qué existe
Esta microfase existe para **Breadcrumbs y context actions** dentro de la responsabilidad de `F06`: añadir capacidades avanzadas/responsive sobre Puck. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **Breadcrumbs y context actions** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

## Engine owner
`Puck extensions + Electro layout/style`

### Regla
Antes de escribir código, consulta la API pública del engine. Si ya existe la capacidad, úsala. ElectroCraft solo debe aportar canonical mapping, configuración, UX, adapter, target semantics o exportación.

## Packages/área de código
`editor-puck + domain + studio/editor`

## Ubicación visual
Editor dentro del AppShell: Components/Screens/Outline a la izquierda, Canvas central, Inspector derecho.


## Ubicación de código obligatoria
- `packages/editor-puck/`
- `packages/design-system/`
- `apps/studio/src/features/editor/advanced/`

## Ubicación exacta en la app
`Construir > Editor`, franja inferior/superior del Canvas contextual y Context Menu.

## Diseño visual exacto
Breadcrumbs jerárquicos compactos; context menu shadcn/Radix con acciones españolas.

## Texto visible en español
Anular; Restablecer; Heredado de; Visible; Ocultar; Agrupar; Desagrupar; Guías; Ajuste; Regla.

## Ayuda contextual
Usa HelpRegistry `help.editor.advanced`. Si esta microfase introduce un concepto nuevo, añade/actualiza su HelpDescriptor en español. La ayuda crítica no puede vivir solo en un tooltip.

## Precondiciones
- `M06.5` COMPLETADA.
- Engine owner disponible detrás de su adapter.
- No existen errores P0/P1 de la dependencia inmediata.
- Tests existentes están verdes antes de modificar comportamiento.

## Implementación línea por línea
1. Breadcrumb ancestry Page>...>Selected.
2. Context menu usa selection actual.
3. Copy/paste/save-as-block usan canonical subtree mapping.
4. Lock maps permissions when possible.
5. Visibility es canonical node condition/style property.
6. Extiende canonical Layout/Style/Responsive metadata.
7. Implementa overlay/control solo para gap no cubierto por Puck.
8. Conecta Inspector/Canvas sin almacenar transient geometry innecesaria.
9. Añade keyboard alternative a pointer interaction.
10. Prueba desktop/tablet/mobile y target diagnostics.

## Artefactos obligatorios al cerrar
- `workflow/provider adapter or node definitions`
- `execution/error/history test`

## Flujo de datos obligatorio
1. Usuario/Runtime produce una intención.
2. UI/hook llama al adapter o application service propietario.
3. El engine OSS ejecuta la responsabilidad que le pertenece.
4. ElectroCraft normaliza solo lo que necesita persistencia/portabilidad.
5. Storage o target adapter persiste/ejecuta.
6. Resultado tipado vuelve a UI/runtime.
7. Error/diagnostic permanece visible y reparable.

- reconstruir una función disponible en el engine;
- añadir subsystem/widget/model únicamente por conveniencia;
- persistir engine internals como proyecto canónico;
- usar datos hardcoded permanentes;
- declarar COMPLETADA sin evidencia.

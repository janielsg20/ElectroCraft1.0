# M09.10 — Implementar facets, counts, chips y apply modes

**Fase propietaria:** F09 — Consultas, bindings, listings y filtros

## Por qué existe
Completar el comportamiento tipo smart filters usando el GenericFieldIndexer, no un motor facetado separado.

## Resultado exacto
Al cerrar esta microfase, **Implementar facets, counts, chips y apply modes** debe quedar integrado, persistido/exportable cuando corresponda y cubierto por pruebas. No basta con un tipo, un botón o un placeholder.

## Engine owner
`React Query Builder + TanStack Query + PGlite query adapter`

## Responsabilidad ElectroCraft
Construye únicamente la semántica portable, adapter, configuración, UX y diagnostics que el engine no trae. No dupliques el motor.

## Implementación línea por línea
1. Filter config añade `faceted`, `showCount`, `showChips`, `hierarchical` y `applyMode`.
2. Facet counts usan `record_field_index` y current filter context; no recorren todos los JSON records en UI.
3. Applied chips representan FilterState y permiten remove-one/clear-all.
4. `live` aplica con debounce; `manual` acumula draft state hasta Apply; `url` sincroniza; `reload` se reserva para server target/full reload.
5. Result count proviene del Query runtime.
6. Indexer stale/rebuild state debe mostrarse como diagnostic, no count incorrecto silencioso.
7. WordPress/LAMP compilers seleccionan AJAX/full reload según target configuration.
8. Prueba faceted taxonomy + range + chips + pagination.
9. Actualiza Query/Binding portable definition.
10. Usa RQB solo para condition authoring.
11. Compila a DataSource operation; TanStack Query posee cache en JS runtime.
12. Conecta Listing/Filter/Inspector.
13. Prueba types, invalid rule fail-closed, cache/invalidation.

# M23.9 — iOS exporter y build

**Fase propietaria:** F23 — Capacidades Native y exportación Android/iOS

## Por qué existe
Esta microfase existe para **iOS exporter y build** dentro de la responsabilidad de `F23`: generar y validar Android/iOS con Expo. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **iOS exporter y build** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

## Engine owner
`Expo/Gradle/Xcode`

### Regla
Antes de escribir código, consulta la API pública del engine. Si ya existe la capacidad, úsala. ElectroCraft solo debe aportar canonical mapping, configuración, UX, adapter, target semantics o exportación.

## Packages/área de código
`export-native`

## Ayuda contextual
Usa HelpRegistry `help.export.mobile`. Si esta microfase introduce un concepto nuevo, añade/actualiza su HelpDescriptor en español. La ayuda crítica no puede vivir solo en un tooltip.

## Precondiciones
- `M23.8` COMPLETADA.
- Engine owner disponible detrás de su adapter.
- No existen errores P0/P1 de la dependencia inmediata.
- Tests existentes están verdes antes de modificar comportamiento.

## Implementación línea por línea
1. Genera proyecto Expo/iOS source/Xcode-compatible output.
2. Ejecuta install/typecheck/prebuild iOS cuando environment lo permite.
3. Source siempre se valida independientemente del signing.
4. Build/IPA local requiere macOS/Xcode/signing real; de lo contrario reporta requisito, no failure falso.
5. Nunca claims IPA without file verification.
6. Test source generation and environment diagnostics.
7. Deriva permissions/modules desde CapabilityRegistry.
8. Genera Expo source/config.
9. Ejecuta prebuild/build cuando toolchain real existe.
10. Verifica artifact en filesystem; no infieras éxito.
11. Prueba Android/iOS target report.

## Artefactos obligatorios al cerrar

## Flujo de datos obligatorio
1. Usuario/Runtime produce una intención.
2. UI/hook llama al adapter o application service propietario.
3. El engine OSS ejecuta la responsabilidad que le pertenece.
4. ElectroCraft normaliza solo lo que necesita persistencia/portabilidad.
5. Storage o target adapter persiste/ejecuta.
6. Resultado tipado vuelve a UI/runtime.
7. Error/diagnostic permanece visible y reparable.

## Prohibido
- reconstruir una función disponible en el engine;
- añadir subsystem/widget/model únicamente por conveniencia;
- persistir engine internals como proyecto canónico;
- usar datos hardcoded permanentes;
- declarar COMPLETADA sin evidencia.

# M21.1 — WebRuntimePort y renderer React DOM

**Fase propietaria:** F21 — Runtime Web y exportación React/PWA

## Por qué existe
ElectroCraft es un App Builder; el runtime Web debe existir como producto independiente del editor antes de exportarlo.

## Resultado exacto
Al cerrar esta microfase, **WebRuntimePort y renderer React DOM** existe como capacidad real, conectada a los contratos de ElectroCraft y demostrada con pruebas. No se acepta placeholder, botón decorativo ni contrato sin consumidor.

## Engine owner
`React DOM + ElectroCraft renderer contracts`

## Responsabilidad ElectroCraft
ElectroCraft conserva únicamente la semántica portable, la UX española, los adapters, permisos, validación, persistencia y compatibilidad multi-target. El engine OSS conserva la responsabilidad técnica para la que fue elegido.

## Ubicación de código obligatoria
- `packages/runtime-web/`
- `packages/export-web/`
- `packages/export-core/`

## Ubicación exacta en la app
`Publicar > Vista previa > Web` consume este runtime; no crea una pantalla de configuración propia.

## Diseño visual exacto
Renderer sin chrome del Studio. Usa rutas/pantallas reales, estados loading/empty/error y design tokens del proyecto.

## Texto visible en español
Vista previa Web; Cargando; No hay datos; Error; Reintentar.

## Ayuda contextual
Usa HelpRegistry `help.runtime.web`. El título de pantalla lleva `CircleHelp`; los conceptos técnicos usan `Info` solo cuando aportan contexto real.

## Precondiciones
- Gate de entrada de la fase satisfecho.
- Contratos/engines anteriores verdes.
- No existe una implementación paralela de la misma responsabilidad.

## Implementación paso por paso
1. Define WebRuntimePort/ReactDomRenderer que consume ElectroCraftDocument, Theme, Bindings, State, Queries, Actions y Routes.
2. Mapea Core components a React DOM semantic components.
3. Separa renderer de editor Puck; no importa @puckeditor/core en runtime.
4. Implementa context providers de project runtime mediante adapters.
5. Prueba render de Screen simple, nested slots, bindings y interaction.
6. Congela ExportIR revision.
7. Genera runtime/source mediante shared Web compilers.
8. Genera target-specific package/profile.
9. Ejecuta dependency pruning.
10. Ejecuta install/build/serve/reimport verifier según target.
11. Registra artifact/checksum/report.

## Responsive
- Desktop: alta densidad sin comprimir la tarea principal.
- Tablet: panel secundario a Sheet/Drawer.
- Mobile: flujo por rutas/pasos; no reducir una UI desktop de tres columnas.

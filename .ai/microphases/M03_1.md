# M03.1 — Integrar shadcn/ui Radix, Lucide y tokens Electro

**Fase propietaria:** F03 — Design System, AppShell, español, ayuda e IA de navegación

## Por qué existe
Esta microfase existe para **Integrar shadcn/ui Radix, Lucide y tokens Electro** dentro de la responsabilidad de `F03`: crear UX/AppShell coherentes y simples. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **Integrar shadcn/ui Radix, Lucide y tokens Electro** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

## Engine owner
`shadcn/ui Radix + radix-ui + Tailwind + Lucide`

### Regla
Antes de escribir código, consulta la API pública del engine. Si ya existe la capacidad, úsala. ElectroCraft solo debe aportar canonical mapping, configuración, UX, adapter, target semantics o exportación.

## Packages/área de código
`design-system + studio/shell`

## Ubicación visual
AppShell global, probado en desktop/laptop/tablet/mobile.


## Ubicación de código obligatoria
- `packages/design-system/`
- `apps/studio/src/shell/`
- `apps/studio/src/i18n/`
- `apps/studio/src/help/`

## Ubicación exacta en la app
Studio global: `packages/design-system` y primitives consumidos por todo AppShell.

## Diseño visual exacto
Galería Development de primitives + tokens; release usa primitives dentro de las pantallas, no una ruta propia.

## Texto visible en español
Editor; Pantallas; Plantillas; Componentes; Generar con IA; Contenido; Modelos; Consultas; Formularios; Automatizaciones; Administración; Roles; Medios; Extensiones; Temas; Vista previa; Compatibilidad; Exportar; Desplegar; Ayuda; Configuración.

## Ayuda contextual
Usa HelpRegistry `help.studio.shell`. Si esta microfase introduce un concepto nuevo, añade/actualiza su HelpDescriptor en español. La ayuda crítica no puede vivir solo en un tooltip.

## Precondiciones
- Gate de entrada de `F03` satisfecho.
- Engine owner disponible detrás de su adapter.
- No existen errores P0/P1 de la dependencia inmediata.
- Tests existentes están verdes antes de modificar comportamiento.

## Implementación línea por línea
1. Verifica docs actuales de shadcn y confirma que Radix continúa soportado antes de inicializar.
2. Inicializa shadcn fijando explícitamente `--base radix`; no dependas del default del CLI.
3. Instala únicamente primitives necesarios para el AppShell/Settings/Editor shell.
4. Define tokens semánticos ElectroCraft sobre CSS variables/Tailwind.
5. Define wrappers ElectroCraft solo cuando aportan semántica repetida; no copiar todos los componentes shadcn a otra capa sin razón.
6. Instala Lucide y crea registry semántico de icon IDs.
7. Documenta que AI Elements comparte esta foundation y que no se mezclarán bases `base`/`aria` sin ADR.
8. Crea dev gallery para estados hover/focus/disabled/error/loading/density.
9. Prueba teclado/focus y theme light/dark/system.
10. Actualiza Design System docs/evidence.
11. Añade primitive/composition en design-system solo si no existe en shadcn Radix.
12. Añade i18n keys antes de renderizar copy.
13. Construye composición dentro de AppShell route indicada.
14. Registra HelpDescriptor y Lucide icon ID.
15. Implementa responsive/keyboard/focus states.
16. Añade visual/E2E coverage.

## Flujo de datos obligatorio
1. Usuario/Runtime produce una intención.
2. UI/hook llama al adapter o application service propietario.
3. El engine OSS ejecuta la responsabilidad que le pertenece.
4. ElectroCraft normaliza solo lo que necesita persistencia/portabilidad.
5. Storage o target adapter persiste/ejecuta.
6. Resultado tipado vuelve a UI/runtime.
7. Error/diagnostic permanece visible y reparable.

## Responsive si existe UI
- Desktop >=1280: patrón completo/high density.

- Mobile <768: route/card/bottom-sheet/full-height tool; nunca desktop comprimido.

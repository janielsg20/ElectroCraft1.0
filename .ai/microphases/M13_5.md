# M13.5 — HTTP/REST Provider Registry

**Fase propietaria:** F13 — Acciones, workflows y automatizaciones

## Por qué existe
Esta microfase existe para **HTTP/REST Provider Registry** dentro de la responsabilidad de `F13`: resolver workflows/automation/providers con Rete. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **HTTP/REST Provider Registry** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

## Engine owner
`Rete engine/history + REST provider`

### Regla
Antes de escribir código, consulta la API pública del engine. Si ya existe la capacidad, úsala. ElectroCraft solo debe aportar canonical mapping, configuración, UX, adapter, target semantics o exportación.

## Precondiciones
- `M13.4` COMPLETADA.

- No existen errores P0/P1 de la dependencia inmediata.
- Tests existentes están verdes antes de modificar comportamiento.

## Implementación línea por línea
1. Define ProviderRegistry con `HttpProviderDefinition` versionado.
2. REST operation declara method, URL/path template, query params, public headers, secret header refs, body mapping, response mapping, timeout y retry policy.
3. Runtime usa fetch/client adapter con AbortController/cancellation donde exista.
4. Secret refs se resuelven fuera del canonical project y nunca aparecen en trace/export frontend.
5. Network provider es opcional: core local sigue funcionando si no existe conexión.
6. Offline/unreachable devuelve typed provider error y ActionGraph decide retry/catch/UI feedback.
7. GraphQL NO forma parte del core; puede ser future provider plugin sobre el mismo registry.
8. Prueba GET/POST, timeout, abort, non-2xx y secret redaction.
9. Actualiza ActionGraph/node definition.
10. Mapea a Rete editor/runtime sin persistir classes.
11. Implementa node service/provider adapter.
12. Define target compiler semantics.
13. Prueba graph/history/runtime/loop/error.

# M10.2 — Validation/dedupe/thumbnails

**Fase propietaria:** F10 — Medios y Rich Text

## Por qué existe
Esta microfase existe para **Validation/dedupe/thumbnails** dentro de la responsabilidad de `F10`: gestionar media/richtext. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **Validation/dedupe/thumbnails** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

## Engine owner
`Tiptap + OPFS/PGlite`

### Regla
Antes de escribir código, consulta la API pública del engine. Si ya existe la capacidad, úsala. ElectroCraft solo debe aportar canonical mapping, configuración, UX, adapter, target semantics o exportación.

## Implementación línea por línea
1. Verifica MIME real/content signature, allowed types, size/dimension/duration limits y safe filename.
2. Calcula checksum para dedupe; si existe asset idéntico reutiliza assetId en vez de copiar bytes.
3. Genera thumbnails/previews asíncronos para imágenes/video/documentos cuando el browser/runtime lo soporte; la ausencia de thumbnail no invalida el asset original.
4. Para imágenes raster, implementa un pipeline no destructivo de optimized derivative: max dimension/quality/format policy configurable; conserva siempre el original salvo acción explícita de reemplazo.
5. La optimización usa capacidades browser/worker o un adapter OSS solo si F00/ADR demuestra beneficio; no introduzcas un image-processing framework obligatorio sin necesidad.
6. Guarda derivative metadata ligada al asset original y permite regenerarla; no duplica referencias de uso.
7. Sanitiza SVG antes de preview/render; rechaza contenido ejecutable no permitido.
8. Fonts/icons/documents se almacenan como media con metadata específica; no inventes un storage engine distinto por categoría.
9. Heavy thumbnail/optimization work se ejecuta fuera del render path y soporta cancelación.
10. Prueba dedupe, malicious SVG, oversized image, derivative regeneration, original preservation y cancellation.
11. Define portable media/rich-text payload.
12. Implementa MediaBlobStore o Tiptap adapter; no segundo engine.
13. Conecta Studio UI/field.
14. Implementa target-safe read rendering.
15. Prueba storage/security/round-trip.

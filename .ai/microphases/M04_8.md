# M04.8 — Construir Project Revision Checkpoints y Restore

**Fase propietaria:** F04 — Persistencia local, proyectos y revisiones

## Por qué existe
Separar Undo de sesión de revisiones cross-session y recuperar proyectos sin snapshots completos por cada acción.

## Resultado exacto
Al cerrar esta microfase, **Construir Project Revision Checkpoints y Restore** debe quedar integrado, persistido/exportable cuando corresponda y cubierto por pruebas. No basta con un tipo, un botón o un placeholder.

## Engine owner
`PGlite multi-tab Worker + Drizzle`

Construye únicamente la semántica portable, adapter, configuración, UX y diagnostics que el engine no trae. No dupliques el motor.

## Implementación línea por línea
1. Define revision manifest con projectId, revisionId, timestamp, reason, actor/source y lista de objectId+checksum/version.
2. Crea checkpoints en manual Save Revision, pre-import, pre-destructive migration, publish/export release y coarse automatic interval configurable.
3. Revision no duplica un object payload si el checksum ya existe en la object-version store; reutiliza referencias/versions.
4. Crea UI Project > History/Versions con lista, motivo, fecha y diff summary por object kind.
5. `Restore` no borra historia: crea una nueva current version copiando las refs de la revisión elegida y después guarda un nuevo checkpoint.
6. Engine histories Puck/Rete no aparecen aquí.
7. Prueba restore de una revisión antigua y posterior Undo de sesión independiente.
8. Cambia primero repository/service contract.
9. Implementa Drizzle/PGlite transaction/migration.
10. Conecta use-case; UI nunca llama PGlite directamente.
11. Añade save/reopen/recovery behavior.
12. Añade migration/integration fixture.

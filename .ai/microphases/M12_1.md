# M12.1 — ElectroCraftRole/Permission model

**Fase propietaria:** F12 — Usuarios, autenticación y permisos

## Por qué existe
Esta microfase existe para **ElectroCraftRole/Permission model** dentro de la responsabilidad de `F12`: resolver auth/permissions/audit. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **ElectroCraftRole/Permission model** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

`Refine Access/Auth/Audit`

## Implementación línea por línea
1. Define `ElectroCraftRole` y PermissionPolicy por capability, no por nombres hardcoded.
2. Permission dimensions mínimas: settings, themes/design, content types, create/read/update/delete, publish/moderate, queries, forms, backend/dashboards, media, users/roles, export/deploy, custom routes y project management.
3. Resource rules pueden aplicar a ElectroCraftDataModel/resource IDs concretos.
4. Field rules distinguen `visible` de `editable`.
5. Route rules protegen frontend/backend/custom routes.
6. Action rules protegen mutations/ActionGraph operations, no solo botones.
7. Define presets editables: Administrator, Designer, Editor, Author, Manager, Collaborator, Client, Registered User.
8. Presets son seed configuration; después pueden renombrarse/clonarse sin romper checks porque las features usan capability IDs.
9. Default-deny para operaciones protegidas sin regla/role válido.
10. Validate references and test each preset against representative capabilities.
11. Actualiza Auth/Policy contracts.
12. Implementa provider/evaluator/use-cases.
13. Conecta route/resource/field/action enforcement.
14. Construye Users/Roles/Simulator UI.
15. Añade deny-path tests además de allow-path.

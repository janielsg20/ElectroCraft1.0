# M08.7 — Connector SDK boundary y optional database packs

**Fase propietaria:** F08 — Fuentes de datos, modelos internos, registros y conectores

## Por qué existe
ElectroCraft debe crecer a PostgreSQL/MySQL/Supabase/etc. sin convertir Core en una colección enorme de drivers.

## Resultado exacto
Al cerrar esta microfase, **Connector SDK boundary y optional database packs** existe como capacidad real, conectada a los contratos de ElectroCraft y demostrada con pruebas. No se acepta placeholder, botón decorativo ni contrato sin consumidor.

## Engine owner
`ConnectorRegistry + ElectroCraftExtensionPackage`

## Responsabilidad ElectroCraft
ElectroCraft conserva únicamente la semántica portable, la UX española, los adapters, permisos, validación, persistencia y compatibilidad multi-target. El engine OSS conserva la responsabilidad técnica para la que fue elegido.

## Ubicación de código obligatoria
- `packages/connectors/`
- `packages/data-web/`
- `packages/domain/src/data/`
- `apps/studio/src/features/data/`

## Ubicación exacta en la app
`Datos > Fuentes de datos > Nueva fuente > Más conectores`.

## Diseño visual exacto
Catálogo de connectors con Core/Extensión badge, capabilities y requisito Gateway. Los no instalados abren Extensiones.

## Texto visible en español
Más conectores; Requiere extensión; Requiere gateway; PostgreSQL; MySQL; Instalar conector.

## Ayuda contextual
Usa HelpRegistry `help.data.connectors`. El título de pantalla lleva `CircleHelp`; los conceptos técnicos usan `Info` solo cuando aportan contexto real.

## Precondiciones
- Gate de entrada de la fase satisfecho.
- Contratos/engines anteriores verdes.
- No existe una implementación paralela de la misma responsabilidad.

## Implementación paso por paso
1. Define `ConnectorExtensionManifest` reutilizando ElectroCraftExtensionPackage.
2. Un connector declara source kind, config schema, capabilities, gateway/runtime adapters y target support.
3. Core no incluye drivers SQL server por defecto.
4. PostgreSQL/MySQL se documentan como first optional connector packs after Core stabilization.
5. El catálogo muestra unavailable/installed/version/compatibility.
6. Generated apps reference connector runtime/gateway only when actually used.
7. Prueba extension install/uninstall usage guard y missing connector diagnostic.
8. Define DataSource/DataModel contract/capabilities.
9. Implementa adapter/repository behind ConnectorRegistry.
10. Resuelve secrets por SecretRef/Gateway.
11. Construye Data UI/Explorer/Model UI indicada.
12. Prueba schema/capabilities/CRUD/error/security.

# M03.8 — Diseñar Palette descubrible sin multiplicar componentes

**Fase propietaria:** F03 — Design System, AppShell, español, ayuda e IA de navegación

## Por qué existe
Conservar el catálogo profesional visible aunque internamente muchos items sean presets/composites/aliases.

## Resultado exacto
Al cerrar esta microfase, **Diseñar Palette descubrible sin multiplicar componentes** debe quedar integrado, persistido/exportable cuando corresponda y cubierto por pruebas. No basta con un tipo, un botón o un placeholder.

## Engine owner
`shadcn/ui Radix + ElectroCraft tokens`

## Responsabilidad ElectroCraft
Construye únicamente la semántica portable, adapter, configuración, UX y diagnostics que el engine no trae. No dupliques el motor.

## Ubicación visual
AppShell/Settings/Palette/Inspector dentro del Studio.

## Ubicación de código obligatoria
- `packages/design-system/`
- `apps/studio/src/shell/`
- `apps/studio/src/i18n/`
- `apps/studio/src/help/`

## Ubicación exacta en la app
`Construir > Editor > Componentes` y `Construir > Componentes`.

## Diseño visual exacto
Search arriba; categorías debajo; grid 2 columnas en Context 288 cuando cabe, 1 columna si no; item icono+número de líneas limitado.

## Precondiciones
- La microfase anterior de la fase está COMPLETADA o la dependencia está documentada como ya disponible.
- Los contratos canónicos necesarios existen.
- El engine owner está encapsulado detrás del adapter correspondiente.

## Implementación línea por línea
1. Usa `PALETTE_CATALOG_MATRIX.md` como fuente de verdad; no derives el catálogo directamente de ComponentRegistry.
2. Context Panel Desktop muestra grid compacto de dos columnas cuando >= ancho útil definido; cae a una columna si la descripción/label no cabe.
3. Categorías exactas: Layout, Basic, Content, Navigation, Dynamic Data, Forms, Filters, Social / Contact, Admin, Commerce Pack.
4. Cada item muestra icono consistente, nombre, descripción de una línea y badge opcional Core/Preset/Block/Binding/Alias.
5. Search indexa nombre, función, categoría, keywords, synonym y referencias conceptuales; buscar `posts`, `menu`, `login`, `JetEngine`, `social`, `commerce` debe descubrir las herramientas Electro correctas sin copiar nombres/branding de terceros como UI primaria.
6. Favorites y Recent son workspace preferences que guardan paletteItemId; nunca clonan definitions.
7. Un Palette item Preset/Block crea canonical nodes normales al insertarse; después no requiere un runtime especial.
8. `Navigation` es Core; Mobile Nav/User Menu/Social Icons/Contact Card son presets/blocks.
9. Saved Blocks/Global Components aparecen en su subsección; Custom code components no se ofrecen hasta el future SDK.
10. Drag usa Puck; click-to-insert es alternativa accesible/mobile.
11. Keyboard: focus search -> arrows/tab -> Enter inserts; Escape devuelve foco al canvas/context.
12. Testea búsquedas por nombre/sinónimo/capacidad, favorites/recent, 1/2 columns y no duplicate ComponentDefinitions.
13. Añade primitive/composition en design-system solo si no existe en shadcn Radix.
14. Añade i18n keys antes de renderizar copy.
15. Construye composición dentro de AppShell route indicada.
16. Registra HelpDescriptor y Lucide icon ID.
17. Implementa responsive/keyboard/focus states.
18. Añade visual/E2E coverage.

# M00.3 — POC Visual Editor con Puck Composition

**Fase propietaria:** F00 — Auditoría de producto, OSS y POCs

## Por qué existe
Esta microfase existe para **POC Visual Editor con Puck Composition** dentro de la responsabilidad de `F00`: validar engines, ownership y POCs antes de construir producto. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **POC Visual Editor con Puck Composition** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

## Engine owner
`POCs y engines oficiales`

Antes de escribir código, consulta la API pública del engine. Si ya existe la capacidad, úsala. ElectroCraft solo debe aportar canonical mapping, configuración, UX, adapter, target semantics o exportación.

## Implementación línea por línea
1. Crea un documento canónico mínimo con Container, Text y Button; inserta `Section` como Palette preset que produce un Container con semanticElement=section.
2. Mapéalo a Puck config/data.
3. Renderiza Puck.Components, Puck.Outline, Puck.Preview y Puck.Fields dentro de un shell de prueba.
4. Prueba insert, reorder, nesting slot, edit y undo/redo con historial Puck.
5. Usa onAction para reconstruir/sincronizar ElectroCraftDocument.
6. Verifica que el snapshot Electro no incluya tipos internos Puck.
7. Aísla el experimento; no importes implementación de producto no aprobada.
8. Define fixture mínimo reproducible.
9. Ejecuta la API OSS real que se está evaluando.
10. Mide el gap entre OSS y semántica ElectroCraft.
11. Documenta decisión/limitación/licencia/API usada.
12. Guarda logs/artifacts en evidence.

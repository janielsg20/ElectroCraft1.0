## Reglas
- Puck se consume detrás de `@electrocraft/editor-puck`.
- `ElectroCraftDocument` es el modelo portable; AppState/history/zones no se persisten.
- Usar Composition/Slots/Fields/Outline/Preview públicos de Puck.
- `Puck.Components` y `Config.categories` poseen la lista/categorías; Electro solo añade descubrimiento opcional.
- `Puck.Outline` permanece directo; no usar overrides/plugins experimentales como dependencia release-critical.
- Lock se traduce a permisos públicos Puck; hidden/visibility requiere owner canónico Electro y no se inventa en el adapter.
- Puck `text`/`richtext` + `contentEditable` posee la edición inline; Tiptap es el único engine RichText.
- Diagnostics unknown/unsupported permanecen visibles y reparables, pero no insertables desde la Palette.
- Editor history y Project Revisions son historias separadas.
- Base CI es el gate transversal por defecto.
